# dilla v0.1.0-web3.7: phone app shell, slow mode, announcements, threads — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** dilla looks and works like an app on a phone, and the host enforces who may post.
- **Phone shell.** Under 48rem of viewport, navigation sits at the bottom: **Servers · DMs · Activity · You**. A list pane (rail and channel list side by side) pushes a full-screen view (a channel, a DM, a settings section, the call stage) with a back control. There is no status bar on a phone, only a one-line banner while the link is offline or connecting. One set of call controls: a call bar above the tabs. Tapping a field never zooms the page. Desktop keeps its layout and its status bar.
- **Slow mode and `send_messages` on end-to-end encrypted posts.** Every upload carries a class (post or not). The host refuses a post without `send_messages` and a post inside the channel's slow-mode window. The client waits out slow mode without blocking the group's lane and shows a countdown.
- **Announcement channels.** A text channel where only the ticked roles may post; everyone reads and reacts.
- **Public threads.** Reply in a thread from any message; the thread opens in the aside on desktop and as a full-screen sheet on a phone.
- **Fixes:** a stale call after a reload is left at boot; the SFU clock minors; `dillad doctor` and `dillad admin user` show what operators asked for; the sign-in key step recognises a backup code; the web3.6 security cards; a small debts batch.

**Architecture:**
- **dillad (Go):** migration `00018_message_class.sql` adds `mls_app_messages.class`. A new `ds.PostPolicy` seam (`internal/api/postpolicy.go`) runs inside `ds.Upload` under the group lock. The upload body takes an optional third element; the messages row grows to 9 elements and op 19 `message.ct` to 7. A two-element upload is still accepted in web3.7 (legacy, unchecked). The call leave is bound to its admission's SFU stamp so a rejoin is never cut. Doctor, admin CLI and TOTP/step-up cards.
- **Core (Rust):** the message-row decoder reads 8 or 9 elements and drops a row whose class disagrees with its decrypted type; `send_encrypt` builds the three-element upload. Threads: `app_messages.thread_id` (local schema **5**), `send_prepare` takes a thread id, the main timeline hides held-root replies, roots carry a summary (timeline rows 18 → 19 elements), and two new reads, `thread_timeline` and `threads`. Browser ABI **11**.
- **client-core (TS):** op 19 and the catch-up row carry the class; the send lane requeues on 429 and arms a timer instead of sleeping; a `slow:<channelId>` slice; channel slow mode and the announcement kind; thread commands and slices; a boot-time sweep of stale call groups.
- **packages/ui:** TabBar, PhoneHeader, CallBar, LinkBanner, StateDot; AppShell `layout="phone"`; 14+5 Lucide icons; the glyph sweep and its guard; graduated AudioMeter; ThreadPane, a Composer `notice` slot, a MessageToolbar `thread` item and a MessageRow thread chip; CreateChannel's announcement kind.
- **web:** `layout.ts` (`usePhoneLayout`, `--d-vvh`); routes `/dm`, `/activity`, `/you`; `screens/You.tsx`, `screens/Activity.tsx`, `settings/SignOut.tsx`; the phone composition of `Shell.tsx`; slow-mode Select and countdown; announcement create; ThreadView.
- **No gateway op** (55 stays free), **no permission bit**, **no WASI ABI change** (see Ruling R3).

**Tech Stack:** Go (internal/api, internal/ds, internal/store, internal/auth, internal/ops, cmd/dillad), Rust (core/dilla-core, core/dilla-core-wasm, testkit), TypeScript (client-core worker, React web, packages/ui and Storybook), Playwright e2e against dilla-testhost (Chromium, Firefox, WebKit; phone at 390×844).

## Review Focus

1. **Posting around the host's rules.** A class-0 upload without `send_messages`, inside slow mode, by a second device of the same user, concurrently in one group, with a 4-element or class-2 body, or in a DM. Expected: 403/429/400 as Appendix A says, DMs unchecked, folds never slowed, legacy accepted and unchecked (web3.7 only). Pinned in SB1 (`postpolicy_test.go`: `TestAPostWithoutSendIsForbidden`, `TestSlowModeRefusesTheSecondPostWithItsWait`, `TestConcurrentPostsInSlowModeAdmitOne`, `TestALegacyUploadIsAcceptedUnchecked`).
2. **A host that lies about the class.** A stored class that disagrees with the decrypted type is neither shown nor folded; a legacy row (no class) is accepted; op 19 and the catch-up row agree. Pinned in RB1 (`class_mismatch_is_neither_shown_nor_folded`, `a_legacy_row_without_a_class_is_kept`, `frames.test.ts` case `message.ct with class`).
3. **Thread containment.** A reply whose root is held never shows in the main timeline; a nested thread or an unheld root shows in the channel; a thread id naming a non-post, a reply, or an unheld message is refused; unread and mentions still count replies. Pinned in TB1 (`a_reply_with_a_held_root_leaves_the_main_timeline`, `a_thread_on_a_reply_is_refused`, `the_timeline_plan_uses_the_thread_index`).
4. **A reload never leaves a ghost and a rejoin is never cut.** The boot sweep leaves leftover call groups once; a late webhook, a late pagehide, a second tab, a sign-out during the sweep and an offline boot never cut the new membership. Pinned in 3a-server (`TestALateLeaveNeverCutsANewerAdmission`), 3a-client (`calls/sweep.test.ts`) and E-reload (`reload.spec.ts`: exactly one tile).
5. **The phone shell keeps people oriented and the desktop untouched.** Back from a deep link or a reload, tab memory, sheets closing on the system back, the call bar, no status bar, the offline banner, no auto-zoom on any field, 44px targets, the desktop DOM unchanged. Pinned in W-Phone-2 (`AppShell.test.tsx` phone/desktop), W-Phone-3 (`router.test.tsx` phone back, `viewport.test.ts`, `Shell.phone.test.tsx`) and W-Phone-4 (`phone.spec.ts`: font-size ≥ 16px and `visualViewport.scale === 1`).

## Appendix A: W2b design (from the web3.5 plan :1304-1420, with the web3.7 corrections)

**Scope:**
- an "upload class" protocol change, so the host enforces `send_messages` and slow mode on E2EE posts;
- the slow-mode UI;
- announcement channels;
- public threads.

Not in scope: private threads (a new group target, in a later wave) and cross-server following (spec:225 limits it to readable channels at v1; the integration device is W11 work).

**Reservations (as corrected):** migration `00018_message_class.sql` (both engines) plus `schema/016_message_class.sql` and its Postgres twin; no op (55 stays free); no permission bit; core local schema 5; browser ABI 11; flow doc 11; e2e ports 8501/8502 (E3) and 8503/8504 (E4); string prefixes `slow.`, `announce.` and `thread.`.

**Trust model (§2.2): a host-enforced upload class, verified by receivers.**
- Folding `send_messages` the W2a way would retroactively hide a demoted member's whole history, so it is rejected. Spec:468 binds send permission and slow mode to the uploading device session.
- **Upload body:** `[epoch, private_message, class]`. Class 0 = type 0 (a post); class 1 = types 1–6. The host stores the class and relays it as the 9th element of a message list row and the 7th of `message.ct`.
- **Host rules** (community E2EE text groups only; DMs unchecked):
  - class 0 needs `send_messages` in the channel → 403 E_FORBIDDEN;
  - class 0 is refused 429 E_RATE_LIMITED (`retry_after_ms`, detail "slowmode") within `slowmode_seconds` of the user's last class-0 upload in that channel, unless they hold `bypass_slowmode`.
- **Receiver rule (core):** a stored class that disagrees with the decrypted type (type 0 with class 1, or 1–6 with class 0) is neither shown nor folded. A legacy row with no class is accepted.
- **Correction (web3.7 ruling):** the host **accepts** a 2-element upload as legacy (class NULL, not checked) in web3.7, so open tabs keep working until they reload. web3.8 refuses legacy uploads (400) and raises the hello minimum. The release notes say a crafted legacy upload skips slow mode for one release.
- **Metadata (D2):** the host learns post vs. not-post for every upload. Spec:468 already implies it. Ciphertexts are padded to 256 bytes, so today a short post and a reaction look alike.
- A slow-mode check on every upload would also throttle edits, deletes, reactions and pins: hence the class.
- `http/client.ts:99` (was :95) sleeps on a 429 (unless `retry429:false`) while the group's drain lane is held. Slow mode therefore needs `retry429:false` plus an explicit requeue (CB2).

**Server, SB1 (opus); SB2 is folded into it:**
- **Schema:** `mls_app_messages.class INTEGER NULL` (Postgres `SMALLINT`), plus the index `(group_id, class, uploader_device, created)`. `dump.go`'s DumpTables already lists the table (dump replays by column; `dump_test.go` round-trips the column).
- **Seam:** `ds.PostPolicy`, implemented in `internal/api/postpolicy.go` with the rules above; **correction (R8):** `Check(ctx, g store.GroupRow, userID id.ID, class uint8, now int64) error`. Slow mode is per user per channel across its text groups (join `devices` on `uploader_device`). It reuses the readable-channel arithmetic through a shared `slowmodeWait` extracted from `readable.go:248-270`.
- **Wire:**
  - upload `[epoch, private_message, class(uint 0|1)]`; **2 elements → accepted as legacy in web3.7** (was: 400); class > 1 → 400; other lengths → 400;
  - messages row `[…, deleted, class(uint|null)]` (8 → 9 elements);
  - `message.ct` `[…, recv_ts, class(uint|null)]` (6 → 7 elements).
  - The decode at `internal/api/messages.go:59-63` is a toarray struct; it moves to the raw-array pattern of `channels.go:300-334`. The post policy hooks into `ds.Upload` (`internal/ds/message.go:32`).
