## Global constraints

One complete release, no partial feature release. A failed Spotify qualification
blocks production implementation. Do not substitute YouTube matching, omit Spotify,
or silently reduce playlist functionality. No deployment is authorized by this plan.
Secrets never appear in command-line arguments or logs. Do not log decrypted
messages, commands, excerpts, tokens or provider credentials. No secrets in commits.
User-approved provider revision: evaluate pinned librespot instead of Soloist.
Operator supplies the dedicated Premium account and authorizes it through PKCE;
protected files hold credentials. No Soloist API key or virtual audio sink is needed.
Use existing published crypto constructions. Every commit carries DCO sign-off.

Use at most three child agents alongside coordinator, `gpt-6-luna` by default for
implementation and review. Each gets bounded task brief, owned files, interfaces,
commands, acceptance cases, pitfalls, and changes/tests/issues report. Parallelize
only independent work with stable contracts; separate worktrees for shared files.
Coordinator owns contracts, integration, permissions/crypto review and release gates.
Fresh review for sensitive tasks and whole branch; coordinator independently
verifies identity/authorization/proofs/encryption. Return findings to implementer;
after two unsuccessful rounds coordinator diagnoses. Never reduce tests for cost.

For every task: named failing cases, implement, focused checks, independent review,
signed-off commit. Persist execution progress and evidence; baseline failures
separate from introduced failures.

### Task 0: Establish branch and baseline

Fetch current origin/main and create isolated feat/dilla-bot at its verified
revision; preserve original checkout and .claude/. Reconcile changes since
planning baseline. Save design and plan under docs/superpowers/. Record baseline
test failures. Acceptance: verified remote base and no moved/discarded user work.

### Task 1: Qualify music providers

Build the smallest development-only provider harness. Prove librespot direct PCM output,
playlist handling, controls, restart and Opus production; prove YouTube extraction
with qualified dependencies. Record exact versions and reproducible commands.
Acceptance: real authenticated playback and all required controls on intended
Linux environment. Missing prerequisites remain unqualified; no simulated pass.
Failure blocks production implementation. Full required observations are in the
design's Music section, including no-playback metadata resolution, reboot and
browser decryption. Do not launch with credentials in argv.

### Task 2: Freeze contracts and compatibility

Define helper and bot application schemas, installation/event APIs, role
delegation, moderation proof/feed, receipts, wire/client-upgrade behavior. Update
protocol, vectors and history together. Acceptance: Go/Rust/TS agree on valid and
invalid vectors; malformed and cross-community payloads fail.

### Task 3: Native bot identity and encrypted state

Rust helper, dedicated bootstrap, keyed storage and app-state transactions.
Tests: bot-kind binding, human isolation, wrong/missing key, restart persistence,
key-free logs, transaction rollback.

### Task 4: Installation and revocation

Runtime registration, install lifecycle/enrollment, scoped sessions, managed roles,
explicit moderator-2FA exception. Tests: unauthorized/repeated/interrupted enroll,
rotation, disable/revoke, no administrative token escalation.

### Task 5: Bot network client

HTTP/gateway, heartbeat/resume/discovery, Welcome/commits, durable sync, membership
reconciliation. Tests: expired resume, missed wakeup, generation change, duplicate
Add, revoked device/lost channel, restart during commit.

### Task 6: Event delivery and send receipts

Structural outbox/cursors/operation IDs/retry lookup. Tests: crash either side of
ack, lost send response, retry across epoch, conflicting key reuse, expired event
cursor, duplicate welcome trigger.

### Task 7: Encrypted interactions

Interaction lifecycle, authenticated dispatch/settings, pagination/revisions,
worker bridge. Tests: forged actor, wrong community, removed member, unknown
version, expired command, stale revision, oversized response.

### Task 8: Live encrypted music transport

Bounded live Opus provider in existing media package. Tests: real browser
decryption, microphone slot, epochs, permission loss, cancellation, EOF, stalled
producer and simultaneous independent rooms.

### Task 9: Providers and queues

Integrate qualified librespot/YouTube, durable queues/global Spotify lease/playlist
import/seek/shuffle/repeat/lifecycle. Tests: busy slot, concurrent YouTube,
unavailable track, oversize import, crash, empty channel, paused restart, conflicts.

### Task 10: Music UI and commands

Voice panel and typed command palette. Tests: non-DJ readonly, DJ outside refused,
emergency stop, keyboard reorder, phone layout, error recovery, identical operations.

### Task 11: Welcomes and role selection

Welcome preview/join policy/panels/reactions/grant sources. Tests: rejoin episode,
duplicate event, leave-before-grant, reactor attribution, forged panel, deleted
role, manual grant preserved after reaction removal.

### Task 12: Announcements

Scheduler/recurrence editing/timezones/encrypted persistence/receipts. Tests:
both DST transitions, missed policy, competing attempts, restart after accepted
send, permission loss, deleted destination.

### Task 13: Moderation primitives

Timeouts, signed removal, durable tombstone sync, structural cases, encrypted
evidence attachment/log access. Tests: class-1 bypass, voice unaffected, early
tombstone/late original/edit, stale authority, forged signature, lost notification,
unauthorized evidence query.

### Task 14: Automatic moderation

Rules/config/counters/message+edit/exemptions/actions/retention. Tests: threshold
boundaries, multiple devices, duplicates, old replay, log-only no mutation,
edit violation, byte-bounded UTF-8 excerpts, 90-day purge.

### Task 15: Package and integrate

Wire real routes/workers/lifecycle/UI/health. systemd, guided setup/dependency
checks/backup+restore/diagnostics/release packaging with pinned provider dependencies.
Acceptance: fresh install enables/configures fully through shipping UI and docs.

### Task 16: Whole-release acceptance and documentation

Full matrix, independent review, CI gates. Update README/user/operator guides,
protocol history/screenshots/release notes, actual Spotify limitations and qualified
versions. Acceptance: every feature works together; no partial release.

## Dependencies and ownership

1. Provider qualification and contract preparation.
2. Native storage and server installation after frozen contracts.
3. Interaction and media transport.
4. Music UI/community/moderation on stable interfaces.
5. Integration and full acceptance.

## Integrated acceptance matrix

1. Fresh install, human signup, community creation, enable/configure; no seeded shortcuts.
2. Bot visible with correctly signed identity.
3. Private permission changes add/remove bot access.
4. Two independent sessions within one community.
5. Cross-community identity/queue/key isolation.
6. Actual Spotify audio decrypts in browsers.
7. Spotify contention clearly refuses without interruption.
8. YouTube plays while Spotify active elsewhere.
9. DJ authority revoked during session.
10. Welcomes/autoroles/buttons/reactions survive retry.
11. Announcements survive restart and DST changes.
12. Timeout blocks text/reaction bypass and preserves voice.
13. Moderator removal survives offline recovery and delayed history.
14. Automoderation defaults to log-only.
15. Disable stops actions and revokes access.
16. Backup restore recovers encrypted state with paused queues.

Observe encrypted SFU frames, authorized browser decryption, revoked member
unable to decrypt later epochs, no plaintext fallback. Removing encryption hook
must fail the test. A connection alone is insufficient evidence.

Health covers runtime authentication/helper+DB/sync lag/pending memberships/
provider availability/Spotify authorization+controls+compatibility/PCM output/jobs+retries.
Bounded aggregate metrics exclude text/URLs/names/high-cardinality message labels.
Coordinate separate structural and encrypted-state backups, protect keys,
reconcile older MLS snapshots before sending.

Ready only with all UI features, real Spotify qualification, recorded protocol and
compatibility review, both stores/browser suites, negative security tests,
independent findings resolved, install/upgrade/disable/restore verified, accurate
docs. Prepare reviewable PR and release evidence; live deployment separate.
Offer focused Obsidian save for architecture/qualification/operational lessons
