# dilla v0.1.0-web3.8: Discord-like desktop voice and stage, fast speaking, no status bar, sign-in order, legacy uploads refused, a smaller core, a private data directory — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- **Desktop voice, Discord-like.** The bottom left of the window always holds the user panel (name, mute, deafen, user settings). In a call, the call panel sits directly above it (where, the level, camera, share and leave). The stage's toolbar is pinned to the bottom centre of the stage. Phones are unchanged.
- **A fast speaking indicator.** Speaking is computed in the page from the levels of this device's mic and of each remote audio track. It turns on after about 50 ms above a threshold and off after a 300 ms hold. It never shows while muted, deafened or paused. The SFU's flag stays as the fallback.
- **No status bar on desktop either.** A one-line link banner shows while the link is not online. Node, link, generation and devices live in Settings → Diagnostics (and, on a phone, on You as today).
- **Sign-in order on a new browser:** username and password, then the second factor, then the recovery key last. The key step says the recovery key is not a backup code.
- **Legacy uploads refused.** The host refuses the two-element upload, and the gateway offers only wire version 2. Tabs loaded before web3.8 see "This server needs a newer client. Reload the page." with a reload button.
- **The browser core under 3.5 MB**, with the budget set back to 3,500,000.
- **The invite landing page** (`/i/{code}`) in Mesh style, under the same security limits.
- **Cards from the web3.7 ledger,** grouped into four tasks.
- **Items 9-15 (Jonas, 2026-10-17):** (9) `dillad init` writes its config to `--config`, every file it and `dillad` create in the data directory is owner-only, and the deploy guide explains changing the instance domain; (10) drag or key the borders between the channel list, the conversation and the side panel; (11) "invite link" moves under server settings → invites and "+ channel" becomes a "+" in the channel list; (12) one channel list with voice channels in place and their people nested; (13) a Discord-style user panel at the bottom left with mute and deafen, and settings off the rail; (14) a call stage like Discord's: one tile per camera or screen, a fitted grid, focus with a filmstrip, swap and full screen; (15) participant state glyphs inline on one row, without text labels.

**Next wave (out of scope):** passkey PRF unlocks the key backup, with the recovery key as fallback (Jonas, 2026-10-17, proposed). It is its own E2EE wave.

## Rulings

Built as written unless the controller or Jonas overturns them.

- **R1. Speaking is local; the SFU flag is the fallback.** `update_interval` stays 400 (`internal/sfu/config.go:177`).
  - Every case with a local level (own mic while sending; a remote track that is attached) no longer reads the SFU flag.
  - The fallback covers only a remote track that is not attached (deafened, paused, a volume of 0, no AudioContext), and own speaking without a context.
  - Lowering the interval would double active-speaker signalling to every participant for those cases only.
  - Cost if wrong: the fallback cases stay about 1 s late. No operator change.
- **R2. The hello minimum is wire version 2, advertised alone.** Ruled as written by the controller, carrying out Jonas's ruling that web3.8 refuses legacy clients.
  - **Why a version bump:** web3.6 and web3.7 clients both identify with `['', 1, 1, 1, 0]` (`gateway.ts:208`), so the gateway cannot tell a stale bundle from a current one.
  - **What old tabs do:** every released client since web-1 tears down with the version close when hello lacks 1 (`gateway.ts:202-204`; present at `v0.1.0-web3.6`), and shows `shell.banner.clientTooOld` (en.ts:213 at web3.6). That is the reload path, with no code in the old bundle.
  - **The N-2 exception:** protocol/07 "Negotiation" asks for N-2 support. Before the first public release, the founder's approval plus a recorded review satisfies the change process (07 step 4). H1's row states the exception.
  - **Rejected alternative:** a `caps` bit on identify. It is undocumented semantics with the same blast radius.
  - **Cost:** web3.7.x tabs that already send the class must also reload.
- **R3. Desktop focus and shortcuts (as amended by item 13).**
  - On desktop the user panel's mute and deafen own the shortcuts: they carry `aria-keyshortcuts` (`VOICE_SHORTCUTS`, CallControls.tsx:42) and the shortcut in their tooltip. They exist whenever the desktop shell is shown, in and out of a call.
  - The stage toolbar keeps its own mute and deafen. Its tooltip still shows the shortcut, but its buttons carry no `aria-keyshortcuts` (`keyshortcuts={false}`).
  - The voice dock (the call panel above the user panel) has no mute or deafen: where, the state, the meter, camera, share and leave.
  - The toolbars have different names (`panel.region`, `voice.dock.region`, `voice.controls.voice` / `voice.controls.region`), separate `useToolbarFocus` instances in separate DOM subtrees, and ids from `useId` (CallControls.tsx:135). There is no roving clash and no duplicate id. The ids `dw-voice-dock-paused` and `dw-voice-dock-audio` exist only in the dock.
  - The handler stays the window keydown in `useCall.tsx:527-542`, so a shortcut never depends on which control is on screen. Outside a call it was a no-op (`useCall.tsx:528` returns when `session === null`), so WS6 extends it: with no session, on the desktop shell, Ctrl/⌘+Shift+M and Ctrl/⌘+Shift+D call `selfMute`/`selfDeafen`. The advertised shortcut then does what it says (pre-flight C-10).
  - Join focus still goes to the stage's first control (`useStageFocus`, VoiceView.tsx:161-168).
  - On a phone there is no user panel; the phone call bar and stage keep today's behaviour.
- **R4. Desktop no status bar.**
  - On desktop the AppShell renders no status wrapper and no status grid row. The LinkBanner goes in the banner slot, as on phones.
  - The desktop `shell.banner.offline` Banner is no longer rendered (Shell.tsx:1206 becomes `offline && linkReason === 'version'`). The key stays (no copy lint counts unused keys), so the `shell.` pin stays 177.
  - Node, link, generation and devices live in Settings → Diagnostics, which already lists connection, generation, instance and devices (`DiagnosticsPanel.tsx:21-24`). No new surface.
  - Desktop `/you` keeps redirecting to `/settings/devices` (R12 of web3.7).
- **R5. Announcement self entry (authz, opus).**
  - **Server:** at create only, `createOverwriteRow` (channels.go:454-461) exempts from the rank rule the creator's own user entry whose `allow` is `view_channel`, `send_messages`, or both, with `deny == 0`. `checkBits` still requires that they hold every bit.
  - **Client:** a creator who is neither owner nor administrator always adds `{kind 1, self, allow send_messages}`. The held-role refusal and its dependency on `members:` are removed. This also fixes "create before the member list loads".
  - **Cost:** a creator demoted later keeps `send_messages` in that one channel until someone of higher rank removes the entry. It is visible in the channel's permissions. `putOverwrite` (roles.go:1017) is unchanged.
- **R6. Sign-in order without weakening REGISTRATION-DEVICES-02.**
  - **The protection:** the owner's new device row must not sit registered and unlisted for human time while an attacker who holds the password registers until eviction (`.superpowers/sdd/2026-10-06-dilla-web-2a/branch-review-registration-devices.md:68-93`). It is why the key came first: the key was in hand before the login, and the login and the registration ran within seconds (web-2a plan :796, flow 03 :47-69).
  - **The new order keeps it:** the login and the factor never register. The worker holds the settled assertion (`Enrol.hold`, enrol.ts:29), and the registration runs only inside `signInKey`, after the key's form check, back to back with the fetch, the enrolment and the list PUT (`enrolWithKey`, controller.ts:1910).
  - **A backup code is held in the page,** never spent early. The key step then sends `signInBackupCode { code, recoveryKey }` (its current shape). The server checks the assertion before the code (`verifySecondFactor`, auth.go:785-791), so an assertion that expired during key entry spends no backup code. On this path the expiry arrives as a 401 from `enrol.backupCode`, not from `register`; C1 maps it to `E_SIGNIN_EXPIRED` as well, so the page shows `enrol.expired` and not a raw error (pre-flight C-16).
  - **The TOTP and passkey paths** verify at their own step (a code is time-bound), then hold the fresh 5-minute assertion that `Upgrade` mints (auth.go:106).
  - web3.6's per-account guess ledger is unchanged.
  - **Cost:** reading the key off paper for more than 5 minutes after the factor costs a new login (copy `enrol.expired`).
- **R7. Step numbers.** Login is 1; the second factor (code, passkey or backup code) is 2; the recovery key is 3, or 2 when no factor step was shown (an account that owes a factor and sets one up after enrolment as 3); done is 4.
- **R8. markRead and live-held rows.** The marker is the group head, but stops one below the oldest row in `heldLive` for that group that arrived less than `HELD_READ_HOLD_MS = 60_000` ago. A row released later is then unread, as a live arrival would be. A row held longer stops holding the marker, so no badge sticks.
- **R9. Landscape phones get the phone layout.** `PHONE_QUERY = '(max-width: 47.99rem), (pointer: coarse) and (max-height: 31.99rem)'`, and every `@media (max-width: 47.99rem)` in ui and web gets the same second clause. There are 9 such rules: base.css :98 and :118, six more in `packages/ui`, and app.css:204 in web. Two guards pin them, each in its own lane: U1's `phone-query.test.ts` pins the 8 in `packages/ui/src` (and `base.test.ts:9` `NO_ZOOM` pins the new string), and WS2's `layout.test.ts` pins the web one, so no guard is red before its own lane lands (pre-flight C-6).
  - **The `@container` rules get `[data-layout="phone"]` twins.** The rules `@container d-shell (max-width: 47.99rem)` (base.css:41, MessageRow.css:27 and :56, app.css:103 and :229) are not media queries and cannot see the viewport: at 844×390 the shell is 844px wide while `data-layout="phone"` is set. Each gets a `[data-layout="phone"]` twin with identical declarations (U1 in ui, WS2 in web), so a landscape phone gets the phone DM-call layout and the 44px targets (pre-flight C-7).
  - Tablets (landscape height ≥ 768px) and short desktop windows (fine pointer) keep the desktop layout.
- **R10. The page lock moves to an attribute.** The `layout.ts` hook that Shell calls while the phone shell is mounted sets `data-phone-shell` on `<html>` and removes it on unmount (WS2 owns the hook; Shell sets nothing itself) (pre-flight C-28); `html[data-phone-shell], html[data-phone-shell] body { overflow: hidden; }` replaces app.css:207.
- **R11. The Dock's `noShare` is deleted** (VoiceView.tsx:499 and :543): the Dock is never rendered on a phone (Shell.tsx:950).
- **R12. The outbox same-second order is deferred, not dropped.**
  - The card is real: `ORDER BY created,msg_id` on a WITHOUT ROWID table (schema.rs:148-157, sync.rs:172, messages.rs:1177), where `msg_id` is random by protocol/04:11.
  - The fixes are a store schema 6 column (refuse-and-restore on rollback), or a protocol change to `msg_id`. Both are out of proportion for a reload tie of two posts sent in one second; the in-session order is already kept (FX-core).
  - It rides with the first wave that cuts schema 6.
- **R13. The `dilla_core_wasm_bg.js` card is dropped.** It is the wasm's import module name (`WebAssembly.Module.imports` lists only `./dilla_core_wasm_bg.js`), which wasm-bindgen's glue keys the import object by. Nothing fetches it. DOCS adds one line to the deploy README so an operator's 404 check skips it.
- **R14. The vector runner leaves the browser build.**
  - `dilla-core-wasm` gets `[features] vectors = ["dilla-core/vectors"]`, off by default. `vectors_check_json` and `vectors_check_ok` are `#[cfg(feature = "vectors")]`. The CI step `cargo test -p dilla-core-wasm --target wasm32-unknown-unknown` gains `--features vectors`.
  - No TypeScript calls either export (grepped across packages, e2e and spike, excluding generated bundles), so browser ABI 11 stays.
  - Conformance stays in three places: the node test under wasm32, the native tests, and the WASI build.
- **R15. Invite page OpenGraph.** `og:title`, `og:description`, `og:type` (`website`) and `<meta name="description">` name the community and the instance only. Anyone holding the URL already gets both, from the HTML today and from the CBOR element 3 (invites.go:157-161). The preview names nothing else.
  - There are no expiry, remaining uses or inviter in the preview (stale once cached), no `og:url` (it would repeat the code), and no `og:image` (no external reference and no new route).
- **R16 (9a). init writes the config to `--config`.**
  - `runInit` defines `-config` through `newFlagSet` (`cmd/dillad/version.go:18-23`, default `/etc/dilla/dilla.toml`) but today writes `<data-dir>/dilla.toml` (`init.go:64`, written at :171), which `install.sh:719-725` copies and deletes.
  - It refuses an existing config file unless `--overwrite-config` is given.
  - It still refuses a data directory that is already initialised, flag or not. "Initialised" means it holds `dilla.db`, or a `dilla.toml` left by an older init.
  - Cost: a script that read `<data-dir>/dilla.toml` after init breaks. The only one in the repo is `deploy/install.sh`, which this wave changes.
- **R17 (9b). File modes.**
  - `dispatch` (`cmd/dillad/main.go:60`) sets the process umask to 0077 first thing, on unix builds.
  - `sqlite.OpenWrite` (`internal/store/sqlite/open.go:78`) pre-creates the database file at 0600 and `chmod`s it to 0600. SQLite's unix VFS creates `-wal` and `-shm` with the database file's own mode; that is SQLite's documented behaviour, and OPS1's test proves it.
  - A helper `sqlite.SecureFiles(path)` `chmod`s `path`, `path-wal` and `path-shm` to 0600 and ignores a missing file. Init calls it after the migrations; `serve` calls it after its write open (`serve.go:54`), which also repairs existing installs.
  - Init `chmod`s the data directory to 0700 even when the directory already existed.
  - The umask covers the rest: blobs, the lock file and ACME files. `UMask=0077` in `deploy/dilla.service` hid this under systemd only.
- **R18 (item 10). Pane widths in localStorage.**
  - Pane widths are the one Web Storage use outside the session-scoped tab memory: key `dilla.paneWidths`, JSON `{"sidebar":px,"aside":px}`, read and written only in `packages/web/src/layout.ts`.
  - The `eslint-disable-next-line no-restricted-globals` reason reads: "a pane width is a per-viewer convenience, not a key, token or state worth protecting" (the form of `layout.ts:54`).
  - `packages/ui` never touches storage. AppShell takes the widths in and reports them out.
  - The splitters are desktop only. The aside splitter exists only while the aside is a column (shell ≥ 64rem, `COLUMN_REM`, `AppShell.tsx:52`).
- **R19 (item 10). The copy prefix is `pane.`, not `shell.resize.*`.** `strings.test.ts:79` pins `shell.` at 177 keys.
- **R20 (item 11). Invites stays visible to anyone with CreateInvite.**
  - ServerSettings already gates its Invites tab on `access.createInvite` (`packages/web/src/screens/admin/ServerSettings.tsx:66`).
  - Its active tab falls back to the first permitted tab (`:70`). So "server settings", opened at `'overview'`, lands a member who holds only CreateInvite on Invites.
  - The header's "server settings" button already shows for every member (`Shell.tsx:917`). No new gating is needed.
- **R21 (item 11). The "+" reuses `create.channel.open` ('new channel', en.ts:573).** No "create channel" key exists.
- **R22 (item 12). ActiveVoice is deleted.**
  - Its only users are `ActiveVoiceList` in `VoiceView.tsx:446-452`, mounted at `Shell.tsx:926` (phone tabs) and `:931` (desktop), plus its own stories, test and `AppShell/VoiceStates.stories.tsx`.
  - Both mounts go in WS5, and WS5 then deletes `packages/ui/src/ActiveVoice/**`, its `index.ts` export and its use in `AppShell/VoiceStates.stories.tsx`. U3 leaves ActiveVoice in place, because `VoiceView.tsx:8` imports it until WS5 and G-ui runs the web typecheck (pre-flight C-1).
- **R23 (item 13). The user panel spans under the rail, as in Discord.**
  - The desktop grid's last row becomes `"panel panel main"` (with an aside: `"panel panel main aside"`). The voice dock sits in the same area, above the user panel.
  - This is cheap because R4 removes the status row: the change costs one area, not a new row.
- **R24 (item 13). Clicking the name block opens Settings; there is no popover.**
  - ActionMenu's trigger is an icon button (`ActionMenu.tsx:30`), so a name-block popover would need a new component. That is out of proportion for one "copy username" item.
  - The name block is a pointer target only (a `div` with `onClick`, no role and no tab stop). The gear is the keyboard path, so there are no duplicate tab stops.
- **R25 (item 13). Mute and deafen outside a call write the existing device-local `voice.self` setting.**
  - The setting is `SETTINGS.voiceSelf` (`packages/client-core/src/state/settings.ts:33`, values `'muted' | 'deafened' | null`). Joins already start in it (`useCall.tsx:306`), and calls already write it (`keepSelf`, `:363-366`). No new client state.
  - Outside a call:
    - mute: `null` → `'muted'` → `null`; from `'deafened'` it goes to `null` (unmute also undeafens, like `setMuted(false)` in `session.ts:966`);
    - deafen: `null` or `'muted'` → `'deafened'`; from `'deafened'` it goes to `'muted'` (privacy-safe, like session fix round 3 m1).
  - In a call the buttons call `call.toggleMute` and `call.toggleDeafen`.
- **R26 (item 14). Auto-focus, as one rule.** When a screen tile of another person appears while no tile is focused, it takes focus. Nothing else ever focuses a tile automatically. A tile the person unfocused is never re-focused by the same share. The own screen never auto-focuses.
- **R27 (item 14). No re-parenting.**
  - Tiles are one keyed list (`${deviceId}:${source}`, source ∈ camera, screen, avatar), always in the same DOM order. A device has one person tile (`camera` with a verified stream, else `avatar`) and, while it shares, a `screen` tile (pre-flight C-9).
  - Focus changes only `data-focused` on the stage and the tile. CSS grid placement does the rest: the focused tile spans row 1, and the others flow into the filmstrip row.
  - `StreamVideo`'s effect depends on `stream` only (`CallTile.tsx:63-71`), so nothing reassigns `srcObject`.
- **R28 (item 14). The tile is not a button.**
  - A focus `<button>` covers the tile's media. It is named by the tile's title and toggles with `aria-pressed`.
  - The full-screen button and the volume slider are siblings of it, never inside it, because a button may not contain interactive content.
  - Volume stays only on a person's camera or avatar tile. The state glyphs stay on that person tile too, so someone who shares only a screen keeps both (pre-flight C-9).
- **R29 (item 15). Which states become glyphs.** Muted (`mic-off`), deafened (`headphone-off`), camera (`video`) and screen (`monitor-up`) are 14px icons, and speaking is `StateDot tone="ok"`; none has a visible word. Each is `role="img"` with `aria-label` set to its `voice.state.*` word and a native `title` with the same word as its tooltip (a non-interactive glyph cannot take focus, so the tooltip is not the only carrier of the name). The stream states `connecting`, `not heard yet` and `unverified stream` keep their glyph and word, because they are trust and diagnosis states (L-UI-61…69); they follow the icons on the same row. The `web` and `bot` tags stay text tags.
