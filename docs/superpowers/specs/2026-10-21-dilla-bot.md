# Dilla Bot design

Status: approved user intent; implementation is gated on provider qualification.
Source: the user's “Dilla Bot: implementation and delegation plan”, supplied 2026-10-21.
Execution plan: [tasks and release gates](../plans/2026-10-21-dilla-bot.md).
This document records intended behavior, not shipped functionality.

## Delivery contract

Deliver one complete release of a configurable built-in community bot: music,
welcomes, roles, announcements, and moderation. Each community has an independent
identity, editable name and avatar. Run a separate Linux service alongside dillad
with guided installation and configuration in Dilla server settings. Reuse internal
components; no public SDK or third-party bot installation in this release.

Music requires YouTube and actual Spotify audio through Soloist, using one
operator-provided dedicated Premium account and one active Spotify session across
the installation. Multiple independent music sessions may run per community.
Provide slash commands and a music panel; configured DJs must be in the controlled
voice channel. Owners and administrators retain emergency stop.

Required controls: search, links, playlists, pause, skip, stop, seek, volume,
shuffle, repeat, removal, and queue reordering. Empty channels pause immediately,
disconnect after five minutes, and retain queues. Restart restores queues paused.
Default text search is YouTube; Spotify accepts track, album, playlist links/URIs.
Default installation session limit is eight, operator configurable; queue limit is
500 per channel. Oversized playlist imports fail atomically.

Community tools: public welcome and one automatic join role; self-service role
buttons/selectors and emoji reactions; one-off, daily, weekly announcements;
warnings, text timeouts, kicks, bans, message removal; automatic spam, duplicate,
and mention-flood rules. All channels allowed by assigned permissions are eligible.
Evidence includes reason and excerpts bounded to 512 UTF-8 bytes, retained 90 days
by default. Automoderation starts disabled, newly enabled rules log only. No
automatic bans, AI moderation, recording, transcription, local library, or other
music services. Announcement timezone defaults to Europe/Stockholm (IANA names).

## Processes and encrypted storage

Go `dillabot` owns lifecycle, provisioning coordination, new HTTP/gateway clients,
reconnection/sync/events, features, schedules, queues, subprocesses, independent
LiveKit sessions and SFrame key rings, health and diagnostics. Keep media
dependencies out of dillad. The media test bot remains a reference/test peer.

A native Rust helper based on dilla-core owns credential generation and signed
device lists, keyed SQLCipher, MLS membership/Welcome/commits/encryption,
authenticated user/device attribution, durable cursors/send state, call keys, and
encrypted application-state transactions. One helper and serialized mutation queue
per community identity; media pumps may run concurrently without concurrent core
state mutation. The server-side WASI module is not a complete client.

Key the database before any query or schema access; verify decryption by a real
query. Separate community directories mode 0700, secret files 0600. Secrets enter
through protected files, systemd credentials or inherited descriptors, never
command-line arguments. Never log decrypted messages/commands/excerpts, tokens,
provider credentials or SFrame keys. Protect WAL/temp/crash/backup files too.
The operator runs a decrypting member; visibly identify the bot and its channel
membership. Ordinary server message storage remains encrypted.

Private inherited Unix socket only, no network listener. Length-prefixed
deterministic CBOR version 1, maximum frame 1 MiB. Request
`[version, request_id, operation, payload]`, response
`[version, request_id, status, payload]`. Reject malformed lengths and unknown
operations. Narrow operations: open state, bootstrap, sessions, KeyPackages,
group sync, send, call epochs, moderation signatures, application transactions.
Never expose generic SQL or raw identity private keys.

## Identity, authorization and recovery

Operator registers narrowly scoped runtime credential through `dillad admin`.
Authorized human enables bot; server creates pending installation; runtime claims
it and creates independent native identity; dedicated enrollment validates account
and device; publish signed device list and KeyPackages; ordinary permissions and
MLS admit it to eligible channels. Readiness requires enrollment and required joins.
Runtime credentials cannot grant instance administration or existing private keys.
Bind sessions to installation/account/device. Disable/uninstall revokes sessions
and removes memberships normally.

Dedicated bootstrap uses `Kind::Bot`, native device tier and native signer tier
consistently across account, device credential, signed device list and MLS.
Human signup cannot create bots. Ordinary roles and overwrites govern access;
never grant administrator or unrestricted manage_roles to the bot.

| Configuration/action | Human authority |
| --- | --- |
| Enable/general settings | manage_community |
| Join/self-service roles | manage_roles plus rank/permission ceilings |
| Removal | manage_messages |
| Warnings/timeouts | moderate_members (next free bit, baseline bit 24) |
| Kick/ban | existing kick/ban permissions |
| Evidence reading | fresh view_audit_log check |
| Music | configured DJ role and voice-channel presence |

Update masks/editors/vectors/hierarchy/moderator-factor logic together for the new
bit. A managed bot may bypass human moderator 2FA only for a validated installation
and explicitly approved capabilities; configuring human still authorizes and
steps up. `kind=bot` alone is insufficient; human requirements stay intact.

Durable community structural stream covers membership episodes, installation,
permission/channel changes, moderation actions, approved role-panel changes. Each
event has stable ID, monotonic sequence, community, timestamp, subjects and needed
metadata. Retain 30 days. Gateway is a wakeup; stream is recovery source. Persist
progress before acknowledging. Expired cursor reconciles current state, reports a
gap, and never invents historical welcomes. Message content stays in MLS streams.

Stable operation IDs: welcome installation+membership episode; announcement
schedule+occurrence; role change selection/source event; moderation request or
source-message/rule; music interaction request. Send receipts resolve lost replies.
Retry original operation ID, resolve uncertain outcomes before re-encrypting or
resending; conflicting reuse fails.

## Protocol and UI

Routes remain `/v1`; negotiated wire version advances 2 to 3 for new capability
and sync contract. Add installation, runtime enrollment/revocation, structural
events/acks, role policy/selection, timeout, moderation action/recovery and send
receipt families, using existing deterministic CBOR, IDs, errors and authorization.

Use MLS interaction groups with eligible human devices and bot device, normal
identity validation, and `dilla.bot/1` payloads inside existing type-0 envelopes.
Body limit remains 4,000 bytes; paginate by encoded size. Include request ID,
community/optional channel, typed operation/args, revision as applicable, expiry,
response status and stable error code. Derive actor from authenticated MLS sender,
never a JSON user field. Live mutations expire in 30 seconds. E2EE and media stay
version 1; no new envelope type, migration or SFrame slot.

Sensitive templates/text/queues/reasons/excerpts live in encrypted bot state and
encrypted interactions. Server stores only structural authorization constraints.
Settings and queues use revision checks, conflict plus refreshed state on staleness.
Settings pages: overview/status, music, welcomes, self-service roles, announcements,
moderation, moderation log. Voice music panel is full-screen on phones with return
path. Reuse existing frame/components/themes/worker bridge/state/localization/a11y
and initial mockup layout. Web never connects to provider processes. Commands and
controls call the same operations. Destructive manual moderation uses initiating
human server session. Enforce bot capability on negotiated server sessions, not
free-form headers; show clear upgrade requirement for bot-enabled functionality
and preserve supported older connections elsewhere.

## Music

Provider resolves descriptors, starts at position, produces bounded live Opus,
pauses/resumes/seeks/stops, reports metadata/position/completion/failure and cleans
every subprocess/descriptor on cancellation. Descriptor: stable queue-item ID,
provider, canonical source, bounded metadata, optional duration, requesting member.
Dilla owns queue order, shuffle, repeat and transitions.

YouTube uses qualified pinned yt-dlp, required JS runtime/support and ffmpeg.
Allow search and supported HTTPS YouTube video/playlist URLs only. Reject other
extractors/schemes/local files/credential URLs/hosts. Argument arrays, bounded
metadata/time/redirects/process lifetime/memory; network isolation blocks private
infrastructure and metadata endpoints. Surface unavailable/restricted/failure states.

Spotify uses operator-obtained Soloist; do not redistribute it. Dedicated
service-owned PipeWire/PulseAudio server and virtual sink, exclusively routed
output, monitor capture, ffmpeg Opus, existing SFrame/LiveKit transport. Isolate
unauthenticated WebSocket control from browsers and unrelated local processes;
loopback alone is inadequate. Operator supplies API key and pairs dedicated
Premium account. Track build expiry (planning assumption: 90 days) and replacement.

Qualification must demonstrate headless service-account pairing/playback, restart
and reboot, capture without physical device, track/album/playlist handling, complete
playlist expansion, pause/seek/transitions/completion, no playback during metadata
resolution, and encrypted playback in real browsers. Command acknowledgement is
not audio evidence. Failure blocks production implementation and release; never
substitute YouTube matching or omit Spotify/playlist functionality. Spotify's
published policy restriction on broadcasting remains external and unresolved.

Publish microphone source/slot with visible music name: 48 kHz stereo, 20 ms,
96 kbps Opus, DTX off. Subscribe to no participant media. Derive/rotate each call's
MLS keys; independent key rings/buffers/cancellation/provider state. Pause
publication without current keys or authorization. Only one global Spotify lease;
busy never steals. Mixed queue pauses on blocked Spotify item until DJ resumes.
Empty after five minutes: disconnect/release all providers and Spotify lease,
preserve queue. Pause retains position and queue. Stop ends current track and
leaves remaining queue paused; clear is separate. Skip advances once. Repeat is
off/current/queue. Restart never starts audio unexpectedly.

## Community tools

Welcome templates are bounded, support member/server/channel references and
preview without posting. Once per membership episode (rejoin is new); never grant
to someone already gone. Catch up joins from preceding 24 hours, record older as
missed. One join role via server allowlist and rank ceilings.

Only approved bot-authored panel IDs/roles actionable. Buttons use authenticated
human self-selection; reactions use authenticated reactor/uploader, not panel
author. Validate membership/panel/role/allowlist, reject privileged or out-of-rank
policies. Track grant sources so deselection preserves manual grant. Manual revoke
clears relevant sources; later new selection revalidates. Deleted panels/roles
inert; forged lookalike messages cannot grant roles.

Encrypted schedules/occurrences: one-off/daily/weekly in explicit IANA timezone.
Spring gap runs at next valid local time, autumn fold once at first occurrence.
Missed <=15 minutes sends once, older skips. Recheck destination/send permission.
Editing invalidates unstarted old-revision occurrences. Send receipts prevent
duplicates across crashes.

## Moderation

Human sessions and current hierarchy govern manual actions. Before submission,
client persists encrypted evidence outbox by request ID. Bot attaches reason and
excerpt only to matching authoritative accepted server action; failed/forged
requests cannot create completed cases. Bot offline never prevents safety actions:
structural metadata appears immediately, encrypted evidence after sync. Evidence
queries require fresh view_audit_log.

Server timeout expiry blocks community messages/reactions/edits/pins before class-1
shortcut and on readable routes. Keep reading, voice, DMs, MLS handshakes/sync,
own-content deletion and otherwise-authorized private music controls. Composer
shows expiry; expiry works without restart or scheduled cleanup.

Keep author-delete envelope unchanged. Moderator removal is deterministic CBOR
signed in core with device Ed25519 and dedicated domain prefix, containing version,
request ID, actor user/device, community/group, target sequence, request expiry.
Server checks signature/session/current permission/hierarchy; atomically stores
proof/action/removal revision/tombstone; emits deletion after commit. Signature
identifies requester, server decides authority at acceptance. Client durable
tombstones group+sequence include never-downloaded targets. Sync removals before
publishing recovered timelines; late history/edits/search/pins/replies/attachments
cannot resurrect. Markers outlive evidence retention, expired signatures remain
evidence of accepted actions.

Automoderation inspects actually decrypted accessible messages; no ciphertext-size
proxy. Defaults: >5 messages/5 seconds; third identical normalized body/15 seconds;
>5 distinct explicit mentions/message. Exclude bot, exempt owners/admins, other
exemptions explicit. Per rule log/remove/warn/timeout; default log, timeout 10 min.
Server receipt times, edits re-evaluated, deduplicate message+revision+rule.
Recent replay reconstructs windows only; no delayed punishment of old backlog.
Restart-safe purge of encrypted details at default 90 days. Operational audit is
identifiers/metadata only; no promise to erase previously copied evidence.
