# dilla v0.1.0-noise-beta.4

## What's new

- Open tabs loaded from this release check for a newer web build and reload it. The app restores the selected view, drafts, selected attachments, search, scroll position and focus from a short-lived encrypted checkpoint.
- A voice call reconnects after a lost transport. During an app update, a community voice room that closes is reopened automatically for up to two minutes. Camera choice is restored; screen sharing needs another click.
- The LiveKit SFU can run in a separate `dillad media` process. The API can restart while the SFU keeps its rooms, with systemd and Compose recipes for independent processes.

## Operator notes

- The installer migrates an existing `livekit.mode = 'in_process'` configuration to `sidecar`, saving `dilla.toml.prev`. This first migration interrupts calls. It adds and starts `dilla-media.service`; keep both services enabled. Later upgrades restart the API before media. A media restart closes its rooms; the updated community voice client tries to rejoin during the upgrade window. A DM call stays ended.
- Tabs loaded before beta.4 have no update watcher and need one manual reload. An open modal form delays automatic reload until it closes. If the browser cannot save a checkpoint, it offers a manual reload.
- The sidecar's LiveKit metrics are not yet exposed through the API `/metrics` endpoint. Read the media service's own journal for its logs.
- The noise suppression beta remains opt-in. This release adds no server or browser data migration; the server remains at schema 19 and the client store at schema 5.
