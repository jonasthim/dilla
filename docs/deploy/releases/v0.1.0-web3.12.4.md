# dilla v0.1.0-web3.12.4

Released 2026-10-23.

This patch changes the browser client only; the core is byte-identical to web3.12.3's. It fixes three call and messaging bugs, most of them seen in Firefox, and makes `install.sh --check-args` say what it actually checked. No server route, migration or wire format changes.

## What's fixed

- **In Firefox, you hear someone again after they rejoin a call** (#82).
  - **What happened:** a listener on Firefox could hear nothing from a person for more than 30 s after that person reloaded or rejoined. The media server (LiveKit) sends the first audio packets without tagging which slot they belong to, so Firefox sometimes filed them under a spare slot no one was listening to.
  - **What happens now:** dilla notices that case in Firefox and re-subscribes once. The person is heard again about 4 s after they come back.
  - **Diagnostics code:** when it happens, Settings → Diagnostics lists the code `E_MEDIA_MISROUTE`. It is documented in the user guide.
  - **Other browsers:** Chromium and WebKit never trigger it.
  - **Root cause still open:** the cause is in the media server, and a report for LiveKit is drafted.
- **A rejoin no longer fails when another member commits at the same moment** (#83).
  - **What happened:** after a reload, a device rejoining a call could be refused because another member changed the call's group in the few milliseconds between the device reading the group and joining it. The call then ended with "failed". This happened about once in 15 reloads in Firefox.
  - **What happens now:** if the group moved, the device reads it again and retries, at most 3 times. A refusal of a group that didn't move is still final.
- **"is typing" no longer sticks** (#84).
  - **What happened:** a typing notice could stay on screen when its expiry timer fired a millisecond early under load.
  - **What happens now:** each channel keeps one expiry timer. This also stops a member who spams typing notices from piling up timers in everyone's browser.
- **`install.sh --check-args` says what it checked** (#80). On success it now prints `arguments are valid; the release was not checked` on stderr. It checks only the arguments. A mistyped `--version` still passes here and is refused later, at the download, before anything on disk changes. The output goes to stderr so the Proxmox helper's stdout, the invite link, stays clean.
- **A rollback guard in the device-list check is now tested on its own** (#81). A cached device-list row with version 0 or below is refused. The rule is unchanged; it now has its own unit and integration tests. The compiled core is byte-identical to web3.12.3's.

## Operator notes

- **No server change.** There is nothing to configure. The new client and core ship inside the `dillad` release, so this is still a `dillad` upgrade: `install.sh --upgrade --version v0.1.0-web3.12.4`. Open tabs pick up the new build and reload.
- **Upgrades still end live calls.** The installer still restarts the media server (SFU). The work that lets a call survive an upgrade is still in progress and is **not** in this release. Run `dillad media --rooms --config=/etc/dilla/dilla.toml` immediately before the upgrade, and upgrade only when it reports `no live rooms`.
- **Roll back to web3.12.3** with the usual `.prev` swap:

  ```
  systemctl stop dilla
  cp -p /usr/local/bin/dillad.prev /usr/local/bin/dillad
  cp -p /usr/local/bin/dilla_core_wasi.wasm.prev /usr/local/bin/dilla_core_wasi.wasm
  systemctl start dilla
  ```

  The `.prev` pair is web3.12.3's only if this release was installed with `install.sh --upgrade` and nothing was upgraded since.
- **What a rollback does not undo:** nothing. This release changes no client data. A rollback brings back the three bugs above.

## Exercised and not yet seen

- **Exercised:**
  - The Firefox audio recovery fired 6 times in 24 Firefox upgrade test runs and recovered audio every time. Chromium never fired.
  - The rejoin retry ran for real against the real core in 3 of 80 traced Firefox runs. A refused join was retried 373 ms later and succeeded.
  - The typing fix passed 24 Firefox runs and 5 Chromium runs.
- **Not yet seen:**
  - No committed browser test reproduces the Firefox audio misroute on main. It shows up reliably only in the calls-survive-upgrade work's upgrade test.
  - The typing failure itself didn't reproduce locally. The proof is a unit test that fails without the fix.

## Known limits

- The web3.12 known limits still hold.
- Under a heavily loaded single CPU, the first message in a channel can stay "sending…" for a long time. This has a different cause, which has not been looked into yet.
