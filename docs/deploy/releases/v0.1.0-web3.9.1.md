# dilla v0.1.0-web3.9.1

Released 2026-10-21.

A release for [issue #37](https://github.com/jonasthim/dilla/issues/37), "There is no sound when watching another person's stream". It also carries a security update of the Go toolchain and a server fix for a ghost in voice. **Upgrade promptly:** web3.9 was built with Go 1.27.2.

## Security

- **Go 1.27.3** (from 1.27.2) for [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809) / CVE-2026-111943. `crypto/x509` now refuses a set of intermediate certificates that are no longer trustworthy. This matters where the host's trust store has not caught up. dillad verifies certificates on its outbound TLS connections, for example the clock check against HTTPS origins. govulncheck reports nothing affecting dilla on 1.27.3. The Docker image builds on `golang:1.27.3-alpine`.

## Fixed

- **No ghost tile after a call ends.** If a call ended while the server was still handling a join or a track change from the media server, the device was put back into the ended call and shown as present to everyone. Nothing ever removed it. The server now marks an ended call's room and adds nobody to it. Seen when someone reloaded in a call that their own reload then ended.

## What's new

- **A share without sound now says so.** Browsers only give a screen share sound in some cases, and until now dilla published the share without saying anything. Sharing a game window on Linux was the case in #37. Now:
  - the person sharing sees a notice explaining how to get sound;
  - everyone watching sees a "no sound" mark (a speaker-off icon) on the share's tile.

  The notice and the mark clear when the share gets sound or stops. If the share's sound track ends during a share, both appear then.
- **Every share asks for all the sound the browser offers**, and asks the browser to leave the call's own sound out of it (`restrictOwnAudio`), so nobody hears themselves back. The browser's own picker toggle ("Share tab audio", "Also share system audio") is still the consent.
- **A volume and a mute for each person's stream**, separate from their voice.
  - On a computer, the slider and the mute appear when you hover over or focus the share's tile.
  - On a phone, the tile keeps a mute button and a volume button; tapping the volume opens a slider over the tile.
  - "Muted by you" shows a crossed speaker on the mute button.
  - The stream volume is kept in this browser, per person.
- **Which shares carry sound:**
  - a browser tab in Chrome or Edge;
  - a whole screen in Chrome or Edge on Windows and ChromeOS, when "Also share system audio" is ticked;
  - on macOS 14.2 or later, in Chrome 141 or later.

  A window or screen on Linux, and any share from Firefox or Safari, has no sound. A game's or app's own sound there needs the desktop app, which is planned. See [voice](../../user/voice.md).

## Operator notes

- Nothing to configure. The server changes only in the call-ending fix above, and its binary is built with Go 1.27.3. The new browser client comes inside the `dillad` binary, so upgrade as usual (`install.sh --upgrade --version v0.1.0-web3.9.1`). Open tabs pick up the new build and reload.
- Shared sound stays end-to-end encrypted like voice. The end-to-end test checks that the share's audio frames are encrypted, and that the 440 Hz test tone the viewer plays is one their media worker decrypted.
- **Rollback to web3.9** is safe. The stream volume setting stays in the browser and is ignored there.

## Known limits

- On Windows, Chrome and Edge before version 141 may send the call's own sound back through a shared screen or window (an echo). Update the browser.
- In Firefox, the end-to-end test fakes the capture, because headless Firefox has no screen picker. A real Firefox share is not covered by an automated test.
- After a reload, unmuting a stream you muted restores 100 %, not the level you had before muting.
- The web3.9 known limits still hold.
