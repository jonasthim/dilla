# dilla v0.1.0-web3.12.1

Not released yet.

A client-only patch to web3.12's late-rejoin rule, where a call in a background tab could fail to rejoin by itself after a short drop. Nothing about messages, keys or calls changes on the wire.

## What's fixed

- **A short drop in a background tab rejoins by itself again.** web3.12 stops a computer from rejoining a call by itself when it was gone longer than the server's inactive timeout. It notices a sleep as a gap in a once-a-second check. When a tab is in the background, the browser can hold back that check for a few seconds at a time, and each hold-up looks like a short gap. In web3.12 the absence was counted from the start of the longest such gap, so after a minute or so of hold-ups a short drop could say "You left the call while away." and wait for **join voice**, when it should have rejoined by itself. Only servers with a short inactive timeout (1 minute) were likely to see this. Now a gap during which the call stayed connected counts only for its own length, so hold-ups never add up.
- **Side effect at the timeout boundary.** When a computer wakes from a sleep and its call still looks connected for a while before the loss is noticed (up to about a minute), that connected time no longer counts towards the absence. A sleep that ends just under the timeout now rejoins by itself where web3.12 might have said "You left the call while away." A sleep longer than the timeout, or a reconnect that keeps failing after the wake, still does not rejoin by itself.

## Operator notes

- **Client-only.** Nothing to configure and no server change. The new browser client comes inside the `dillad` binary, so it is still a `dillad` upgrade: `install.sh --upgrade --version v0.1.0-web3.12.1`. Open tabs pick up the new build and reload.
- **Check for live calls before you upgrade.** Restarting `dillad` restarts the media server (SFU), which disconnects every live call. Run `dillad media --rooms --config=/etc/dilla/dilla.toml` immediately before the restart, and upgrade only when it reports `no live rooms`.
- **Rollback to web3.12** is the usual `dillad.prev` swap, since no schema, store, wire or ABI changed: `systemctl stop dilla; cp -p /usr/local/bin/dillad.prev /usr/local/bin/dillad; cp -p /usr/local/bin/dilla_core_wasi.wasm.prev /usr/local/bin/dilla_core_wasi.wasm; systemctl start dilla` (the `.prev` pair is web3.12's only if this release was installed with `install.sh --upgrade` and nothing was upgraded since). A web3.12 tab behaves as before.
