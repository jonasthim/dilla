# dilla v0.1.0-web3.8

## What's new

- **Voice on desktop works like Discord.** A user panel sits at the bottom left with your name, mute, deafen and user
  settings. The call panel sits above it, and the call stage's toolbar stays pinned. User settings is no longer on the
  server rail. Mute before a call starts and the call starts muted: your microphone is closed from the first frame, and
  the others see you as muted from the moment you join.
- **A call stage that fills the stage.** One tile per camera or screen. Click a tile to focus it; the rest move to a
  filmstrip, a click swaps them, and a tile can go full screen. Participant icons now sit on one line after the name.
- **A fast speaking indicator.** The ring around a speaker now follows the audio your browser hears, within a beat, not
  the server's flag a second later.
- **No status bar on desktop.** A banner appears only when the link to the server is down. The facts the bar showed are
  in Settings → Diagnostics.
- **Resizable panes on desktop.** Drag the border of the sidebar or the side column, or use the keyboard. Each browser
  remembers its own widths.
- **Invites and new channels.** Invites are under server settings → invites. The channel list has a "+" to make a new
  channel.
- **One channel list.** Voice channels sit in order among the others with the people in them nested underneath. The
  separate "active voice" list is gone.
- **Sign-in on a new browser asks for the password and the second factor first, and the recovery key last.** If someone
  types a backup code where the recovery key belongs, the step says a backup code is not the recovery key.
- **A styled invite page.** `/i/<code>` is now a small card in the Mesh colours, and a pasted link shows a preview that
  names the community and the instance.
- **An announcement channel's creator can always post in it,** even when they are neither the owner nor an
  administrator.
- **Phone fixes.** Landscape, the system back button, focus order, and dialogs and fields that stay above the keyboard.
- **A private Safari window explains itself.** It shows the "unsupported" screen with the reason instead of a generic
  error.

## Also in this release, if you are coming from web3.7.2

These shipped earlier as `v0.1.0-noise-beta.1` to `v0.1.0-noise-beta.5` and are already running on an instance that
deployed a beta. They are new to an instance still on web3.7.x. Read the migration and sidecar notes below before you
upgrade.

- **Presence** (beta.2, beta.3). The member list groups Online, Idle and Do Not Disturb members under their highest role,
  with Offline and Invisible at the bottom, and role headings carry the role colour. Everyone can choose Online, Idle,
  Do Not Disturb or Invisible; the choice follows the account. Online becomes Idle after ten minutes without activity on
  any device. Do Not Disturb stops desktop notifications and ring sounds on every device.
- **Open tabs refresh themselves** (beta.4). A tab loaded from a beta.4 or later bundle checks `/app-version.json`,
  reloads on a new build and restores the view, drafts, attachments, search, scroll and focus from a short-lived
  encrypted checkpoint. A voice call reconnects after a lost transport, and a community voice room that closes during an
  upgrade is reopened for up to two minutes. Tabs loaded before beta.4 have no watcher and need one manual reload.
- **A separate media process** (beta.4). The LiveKit SFU runs as `dillad media` under `dilla-media.service`, so the API
  can restart while calls survive. See the operator notes.
- **Silent AFK voice channels** (beta.5). A community manager can name a voice channel as the AFK destination and a 1, 5,
  15, 30 or 60 minute timeout. The server moves each idle device out of its media room. Activity is per device:
  keyboard, pointer, touch and microphone speech reset the timer.
- **Automatic (beta) noise suppression ships in every release from web3.8 on** (beta.1). The release workflow now
  builds the enhancement assets for every tag, not only `vX.Y.Z-noise-beta.N`, so this release carries the DeepFilterNet
  model and glue and Settings → Voice offers Automatic (beta) beside Off and Lightweight. Off and Lightweight work as
  before.
- CI and release workflows use only commit-pinned actions with hash-verified tools (beta.5). Nothing for operators.

## Operator notes

Upgrade as usual with `install.sh --upgrade`, then ask every user to reload every open tab.

### Breaking for open tabs: wire version 2

The host now refuses the old two-element upload, and the gateway offers **wire version 2 alone** (`hello` and
`GET /v1/instance` both say `[2]`). Every tab loaded before web3.8, web3.7.x included, shows "This server needs a newer
client." with a **Reload** button and does not work until it reloads. Reload keeps the draft. A post such a tab had
already queued fails and can be sent again after the reload. Nothing is lost. A new tab is unaffected.

The old tabs get this screen with no change in their own code: every released client has always closed on a missing
version and shown this banner. A `400 E_INVALID_REQUEST` for a two-element upload is the same refusal on the upload
route.

### Database: no new migration in web3.8

The server schema is **20** and web3.8 adds nothing to it. The migrations are `00019_presence` and `00020_afk`, which came
in from the betas. An instance on noise-beta.5 already has both and is unaffected. An instance still at schema 18
(web3.7.x) applies them on this upgrade, and both only add a table:

| Migration | Adds | Rolling back |
|---|---|---|
| `00019_presence` | `user_presence` (saved status choices) | **Safe.** Drops the table; every account returns to Online. |
| `00020_afk` | `community_afk` (AFK channel and timeout per community) | **Safe.** Drops the table; AFK settings are lost, voice and messages are not touched. |

To go back from schema 20 to 18, stop dilla, run `runuser -u dillad -- /usr/local/bin/dillad migrate down --to=18 --i-know-what-i-am-doing --config=/etc/dilla/dilla.toml`
with the **new** binary, put `dillad.prev` and `dilla_core_wasi.wasm.prev` back, and start dilla. The deploy guide has the
full steps under "Rolling back by hand".

**dillad takes its own copy before it migrates.** With `db.pre_migration_backup` on (the default), `dillad serve` writes
`<db.path>.pre-migration-<unix time>` beside the database before it applies a pending migration (SQLite; `VACUUM INTO`).
It is a real file an operator who skipped the backup step can restore from: stop dilla, remove the database's `-wal`,
`-shm` and `-journal`, and move the copy over the database. It holds the data as it was at the copy, so **everything
written after it is lost**. It is not a replacement for your own backup, and it is not removed for you.

### Browser data: client store schema 5, unchanged (safe)

No browser's store changes. A browser that opened web3.7 or later is already at 5, and opening web3.8 changes nothing.
Rolling back never shows the "too old" screen. The pane widths live in `localStorage` under `dilla.paneWidths`, which
older clients ignore.

### Rollback

**Nothing in web3.8 is irreversible.** The one thing an operator can do that is irreversible is outside the upgrade: a
change of the instance domain (below) costs passkeys for good.

- **To noise-beta.5 (the deployed base): safe on the server.** The schema is 20 on both, so no `migrate down`. An older
  server offers wire version 1 and a web3.8 tab speaks 2, so an open web3.8 tab shows "needs a newer client" and its
  **Reload** fetches the bundle the older server serves. The draft is kept. The 0600 file modes stay, which the older
  release reads as before. noise-beta.5 also has the media sidecar, so the config needs no change.
- **To web3.7.2: safe.** Its host accepts the three-element upload web3.8's client sends. Run `migrate down --to=18`
  first (above) if the database was migrated. `install.sh --upgrade` may have moved `livekit.mode` to `sidecar` and
  added `dilla-media.service`: web3.7.2 does not know that mode, so stop `dilla-media`, restore `dilla.toml.prev` over
  `dilla.toml`, and then start dilla. An open web3.8 tab sees the same reload banner and reloads into web3.7.2.
- `install.sh --upgrade` rolls back by itself when the new binary fails to start.

### `dillad init` changed

- It writes `dilla.toml` to `--config` (default `/etc/dilla/dilla.toml`), no longer into the data directory. It creates
  the directory of that path if needed.
- It **refuses an existing file** at `--config` unless you pass `--overwrite-config`, which replaces it through a
  temporary file. It still **refuses an initialised data directory** (one that holds `dilla.db`, or a `dilla.toml` an older
  init left) whatever the flag: the flag replaces a config, never an instance.
- `install.sh` from this release no longer moves the file. A hand-written script that copied `<data-dir>/dilla.toml`
  after init must drop that step. The Compose recipe passes `--config=/var/lib/dilla/dilla.toml`, because the default
  directory does not exist in the distroless image.
- `install.sh --upgrade` does not run init and is unaffected.

### File modes

`dillad` sets umask 0077 as its first act, so every file and directory it creates is owner-only whatever the caller's
umask: the data directory is 0700 and its files, `dilla.toml` included, are 0600. `dillad serve` also sets `dilla.db`,
`dilla.db-wal` and `dilla.db-shm` to 0600 at each start, so an install made by hand under umask 0022 is repaired by its
first web3.8 start. Other existing files are not changed. If the chmod fails (a file another user owns), `serve` logs a
warning and starts anyway. Check with `ls -l /var/lib/dillad`: files show `-rw-------` and the directory `drwx------`.
Installs under the shipped systemd unit (`UMask=0077`) already looked like this.

### Changing the instance domain

There is a new section for it in the deploy guide. It costs every passkey, every browser's store and every old invite
link, and passkeys do not come back if you move back. Read it before you start.

### Unchanged and changed files

- **The browser wasm core changed.** The conformance vector runner is no longer shipped to the browser. The new file is
  `/assets/dilla_core_wasm_bg-ChbR2kAo.wasm`, **3,058,175 B**, under the 3.5 MB budget. The budget is back to 3.5 MB
  (web3.7 had raised it to 3.6 MB). web3.7.x served `dilla_core_wasm_bg-EXSiojLc.wasm`, about 3.52 MB.
- **The WASI core is unchanged in source** (`dilla_core_wasi.wasm`, the file `install.sh` places next to `dillad`): no
  file under `core/dilla-core` or the WASI crate differs from web3.7.2. Compare its line in `SHA256SUMS` with web3.7.2's
  to confirm the binary.
- The SFU config is unchanged (`update_interval` 400). The fast speaking indicator is computed in the browser.
- No new configuration keys. `[livekit] mode = "sidecar"` and `db.pre_migration_backup` are from the betas.
- No new permission bits, error codes or gateway operations in web3.8. The version close 4006 and `E_VERSION` already
  existed.

### The invite page

`GET /i/{code}` is now styled, within the same CSP (`default-src 'none'; style-src 'unsafe-inline'`) and the same
headers. It is **still inert**: no script, no external reference, no font or image, no form, one same-origin link into
the client. The `og:` and `description` tags name the community and the instance and nothing else. That is already
visible to anyone holding the link. The code, expiry, remaining uses and inviter are not in the preview.

### `dillad doctor`

No change in web3.8. The doctor's checks and output are those of web3.7.2. `dillad init` and `serve` change as above,
and the doctor reads the same config.

### What the host learns

Web3.8 adds nothing. The user panel's mute and deafen state goes out as `voice_self`, which the host already received
and the others already saw. A client now sends it again, up to three times per join, when its own `voice_state` has not
caught up. The upload class the host learns (post or fold) is from web3.7, now required on every upload instead of
optional. Messages stay unreadable to the host.

From the betas, if you are coming from web3.7.2: the host stores each account's presence choice (Online, Idle, Do Not
Disturb, Invisible) and a per-device activity time for presence and AFK. Other members of a shared community see the
derived status; Invisible shows as Offline. Nothing about message content.

### Test host

`dilla-testhost` (a test-only binary, not shipped) gains `-wire` and `/debug/sfu/withhold`.

## Known limits

- **The phone call stage is rough.** On a 360 px phone the tiles are small and do not fill the width, the volume slider
  overlays the avatar and the full-screen button sits on the tile. The polish is queued after this release.
- After a window flips from phone width to desktop width in one session, the sidebar can stay at its minimum width and a
  drag does not widen it until the page reloads. Seen only in a resized test browser.
- A restart of the microphone that was deferred while muted (noise suppression off, in browsers without a live noise
  toggle) can drop the first 100 to 300 ms of speech after you unmute.
- The voice suite has not been run on Firefox locally. CI runs it.
- Rotating a phone remounts Settings and drops an open safety-number comparison.
- Two posts sent in the same second can swap places after a reload (the in-session order is kept).
- Everything under "Known limits" in the web3.7 notes that this release does not name as fixed still holds.
