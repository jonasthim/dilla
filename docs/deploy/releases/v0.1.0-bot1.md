# dilla v0.1.0-bot1

This release introduces Dilla Bot for community administration and music, alongside the server and browser support it needs. The release includes `dillad`, `dillabot`, their matching core modules, Spotify helper binaries, installers, and checksums. Installing the new server does not automatically install or enable a Bot.

## What's new

- A community can enable a Bot for welcome messages, scheduled announcements, moderation, roles, reaction role panels, and music controls. Bot actions are authorized through encrypted interactions and admission checks.
- The Bot can join voice and play YouTube audio. Browser acceptance exercised audible encrypted playback in Chromium and Firefox, including Pause, Resume, Stop, two sessions in one community, and independent sessions in two communities.
- Bot state and its encryption key are stored separately from the server database. The Bot installer creates a dedicated service account and runtime credential, checks dependencies, and keeps a cold backup when upgrading an existing Bot.
- The server and browser add the admission, membership, recovery, and interaction support required by Bot. A paired Bot/server restore and subsequent group heal passed browser acceptance in Chromium.

## Versions and compatibility

| Component | bot1 | Previous release |
|---|---:|---:|
| Server database schema | **47** | 23 |
| Browser client store schema | **12** | 5 |
| Negotiated wire version | **3** | 2 |
| WASI core ABI | **10** | 6 |

This is a coordinated server and browser upgrade. An older server cannot read database schema 47. A browser store that has been opened by bot1 cannot be read by web3.12.4 without clearing its site data and recovering the account. Older open tabs should reload onto the new build before using the upgraded service.

## Operator notes

1. Back up the server database and config before upgrading. For SQLite, keep the installer's pre-migration copy; for PostgreSQL, take and verify an operator backup. Check active rooms with `dillad media --rooms --config=/etc/dilla/dilla.toml` and schedule the upgrade when there are no live rooms. The installer may restart media and end calls.
2. Upgrade the server with `install.sh --upgrade --version v0.1.0-bot1`. Confirm `dillad migrate status`, service health, and browser sign-in before enabling Bot.
3. For a new Bot, follow the [Bot installation guide](../README.md#dilla-bot-installation) using the release's `install-bot.sh`, the instance's public HTTPS origin, and its 32-character lowercase hexadecimal instance ID. Enable Bot per community in **Server Settings > Bot**. For an existing Bot, use `install-bot.sh --upgrade --version v0.1.0-bot1` and retain its cold backup. Protect `/etc/dillabot`, `/var/lib/dillabot`, and the installer backup as secrets.
4. Run `dillabot doctor` and the optional `doctor --youtube` dependency check before enabling music. Follow the guide's pinned local tool versions. A green dependency check verifies readiness, not live provider playback.

### Rollback

Stop Bot and server writes first. The previous `dillad` cannot start against schema 47. Use the **new** binary to migrate the server database down to the previous binary's schema, 23, before restoring the `.prev` server binary and WASI module. Follow [the manual rollback procedure](../README.md#rolling-back-by-hand), including its status check; do not start the old binary against a newer schema. Migrations 24–47 drop Bot and associated server data on downgrade. If down migration fails, restore the verified pre-upgrade database backup instead; writes since that backup will be lost.

A client store opened by bot1 has schema 12. A web3.12.4 browser cannot read it. To use the old browser build, clear that browser's site data and recover the account with its recovery key, or return to bot1. Preserve the Bot's separate state and encryption key together. If Bot was newly installed, disable its service and revoke only the runtime credential created for that installation after recording its ID; see the [Bot recovery instructions](../dilla-bot-spotify-candidate.md#roll-back). An existing Bot's installer backup is required to restore its previous binaries and state.

## Qualification and known limits

- Verify the tagged release build and checksums before installation.
- YouTube browser playback, community role and moderation flows, announcements, and paired Bot/server restore have browser acceptance evidence. These runs do not cover every production environment.
- **Spotify Premium playback is not qualified.** No dedicated Premium account was paired with the candidate. Actual librespot audio, playlist expansion, playback controls, and encrypted browser playback on the intended host remain unverified. The local helper build and synthetic PCM checks do not establish live Spotify support. The planned one-source-to-several-listeners use also requires separate review against Spotify's Developer Policy.
- Bot upgrade across a prior released Bot database schema has not been exercised. Preserve and verify a cold Bot backup before trying it.
