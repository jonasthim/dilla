# dilla v0.1.0-signal1.3

A hotfix release on top of [v0.1.0-signal1.2](v0.1.0-signal1.2.md), PR #132. It fixes the music path. On the Homelab
instance, after signal1.2, `/play` still never played. The release includes `dillad` (with the web client), `dillabot`,
their matching core modules, installers and checksums.

## What's fixed

- **Music search works.** The `/play` picker's search rejected every result with "youtube: invalid or incomplete
  metadata": yt-dlp 2026.10.21 labels search results `YoutubeSearch`, and the Bot only accepted `Youtube`. Search
  now has its own check. Adding a track still requires complete metadata. The picker no longer searches while you
  paste a link, and a failed search says "Music search failed. Try again."
- **A track that can't start no longer blocks the queue.** If the current track couldn't start (on the Homelab
  instance, an old Spotify track while Spotify isn't set up), every Resume retried it, and the tracks behind it never
  played. The Bot now skips a track that fails to start, tries the next one, and posts a notice in the channel the
  command came from.
- **The Bot only joins the call once its audio is ready.** It used to join the call's encrypted group first, fail to
  start the audio, and then be removed by the server about 30 s later. It now prepares the audio first and joins only
  when that worked.
- **Every music start step is logged** (provider check, audio, encoder, call join, call token, room connect,
  publish), with a failure class and ids, never content.

## Known limits (fixed in the next release)

- **Temporary failures can remove tracks.** Any start failure skips the track, including a temporary one such as a
  YouTube rate limit or a network hiccup. A short outage can therefore empty a queue. Skips have no cap per start, and
  while they run, other music commands (including `/stop`) wait.
- **Titles can reach people outside the call.** The skip notice names the track, so members of the command's text
  channel who can't see the voice channel can see the title.
- **`/resume` can fail.** It fails when the command's text channel can't be registered for notices, for example from
  a read-only channel.
- `music.announce` gains a registration step before playback (protocol/10). There is no wire change.

## Versions and compatibility

| Component | This release | signal1.2 |
|---|---:|---:|
| Server database schema | 54 | 54 |
| Browser client store schema | 13 | 13 |
| Negotiated wire version | 4 | 4 |

There are no database migrations.

## Deploy order

1. Back up as usual. Check that no call is live (`dillad media --rooms --config=/etc/dilla/dilla.toml`).
2. Upgrade `dillad` with `install.sh --upgrade`, then ask everyone to reload their tabs: the picker change is in the
   web client.
3. Upgrade `dillabot` with `install-bot.sh --upgrade`.

A queue stuck on a track that can't start clears itself on the next `/play` or `/resume`: that track is skipped.
