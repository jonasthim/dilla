# dilla v0.1.0-realtime1

Security and realtime transport release on top of v0.1.0-signal1.3, PR #134. Upgrade the API/web,
Bot and matching core artifacts from this complete release together.

## Changes

- Genuine presence input and coarse call statistics use the existing authenticated WSS gateway.
  The web app drops unavailable samples, with no HTTP fallback or replay. Build entries arrive
  over that same connection and are verified against the manifest. Periodic version polling is
  removed; startup, foreground, online and reconnect checks remain.
- Updates wait for open dialogs and live/recovering calls, and preserve drafts and selected files.
  Native Bots continue using wire 3. Existing encrypted Bot interactions, AFK commands and SFU
  participant RTT updates keep their documented HTTP paths.
- Ordinary request bodies have a thirty-second read budget, configurable through
  `server.read_body_timeout`. Commit and blob uploads keep their longer budgets.
- Moderation checkpoints, policy activation boundaries and pending actions survive restarts.
  Accepted effects reconcile through immutable receipts; signed removal proofs remain available
  after local membership loss. Durable completion failures do not silently age out of the journal.
- Membership recovery fences stale queued repairs. Bot rate-limit caches have bounded capacity
  without resetting spent allowances during session rotation. Stats admission rechecks current
  authority and uses a bounded worker/device queue.
- Go JOSE advances to 4.1.6 for [CVE-2026-116587](https://github.com/advisories/GHSA-mgcc-cww5-fp2q):
  unsafe embedded private JWK parameters are rejected before key validation, and RSA parsing is
  bounded. The upstream parser now rejects RSA moduli larger than 4096 bits; OIDC providers using
  larger RSA keys must move to supported key sizes before upgrading.

## Versions and rollback

Server schema advances from 54 to **55**. New web connections select **wire 5**; server support for
wires 2–4 and native wire-3 Bots remains. Browser data compatibility is unchanged from signal1.3.

Migration 55's down migration maps selected wire-5 sessions to wire 4 without deleting bearer
sessions. Before returning to signal1.3, use the new server binary's down migration to schema 54
and follow the deployment runbook. Do not roll back below a wire-4 server.

Keep verified server backups and a complete cold Bot config/credential/native-state archive,
plus the exact previous artifacts. Preserve the post-upgrade native state before any rollback;
do not delete moderation checkpoints. Restore a matched cold Bot archive with its matching
helper if native-state compatibility with the previous helper has not been established.

## Deploy

1. Require green PR and merged-main CI, CodeQL, and a complete official release with all checksums.
2. Verify server and cold Bot backups, including an off-guest copy, and check current LiveKit
   participants. Use the official installers without bypassing their active-call guard.
3. Upgrade `dillad` and its media/core artifacts, then `dillabot` and its matching native helper.
4. Verify installed and running artifact hashes, identity/generation, schema, doctors, public
   health and manifest. Monitor service restarts, errors, request rates and Bot reconciliation
   for fifteen minutes.

The known music limitations documented in signal1.3 remain outside this release's scope.
