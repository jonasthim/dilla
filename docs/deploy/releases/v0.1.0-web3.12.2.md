# dilla v0.1.0-web3.12.2

Released 2026-10-22.

This patch changes only the browser client. It fixes two bugs: a message that could stay unreadable for good after a reload, and the Escape key not closing Server settings. Nothing about messages, keys or calls changes on the wire.

## What's fixed

- **A message is no longer stuck as "could not be read on this device" after a reload mid-sync.**
  - **When it happened.** A device reloaded while it was still catching up after joining a server, and a message arrived in that window. The message decrypted fine, but it was held until the device had checked its own account's signed device list.
  - **Why it stuck.** After the reload, one trust pass read the list once for all of the account's devices. The first device accepted it. The same list was then refused as out of date for every other device. Nothing started another pass in a quiet session, so the message stayed unreadable.
  - **The fix.** The remaining devices now continue from the version just accepted. Every list version is still verified, and the list is still read only once.
  - **Coverage.** A new browser test reproduces the race. It failed 3 of 3 in WebKit before the fix and passes 10 of 10 in WebKit, Chromium and Firefox. Red was only shown in WebKit; in Chromium and Firefox it was seen passing, not failing first.
- **Escape closes Server settings after you make a category.** The category dialog briefly stayed open with nothing in it. It took the Escape as its own and left Server settings open. Dialogs now close in the same step that empties them.

## Operator notes

- **Client-only.** There is nothing to configure and no server change. The new browser client comes inside the `dillad` binary, so it is still a `dillad` upgrade: `install.sh --upgrade --version v0.1.0-web3.12.2`. Open tabs pick up the new build and reload.
- **Upgrades still end live calls.** The installer still restarts the media server (SFU). The work that lets a call survive an upgrade is still in progress and is **not** in this release. Run `dillad media --rooms --config=/etc/dilla/dilla.toml` immediately before the upgrade, and upgrade only when it reports `no live rooms`.
- **Rollback to web3.12.1** is the usual `dillad.prev` swap, since no schema, store, wire or ABI changed. Run:

  ```
  systemctl stop dilla
  cp -p /usr/local/bin/dillad.prev /usr/local/bin/dillad
  cp -p /usr/local/bin/dilla_core_wasi.wasm.prev /usr/local/bin/dilla_core_wasi.wasm
  systemctl start dilla
  ```

  The `.prev` pair is web3.12.1's only if this release was installed with `install.sh --upgrade` and nothing was upgraded since.

## Known limits

- The web3.12 known limits still hold.
- Under a heavily loaded single CPU, the first message in a channel can stay "sending…" for a long time. This has a different cause, which has not been looked into yet.
