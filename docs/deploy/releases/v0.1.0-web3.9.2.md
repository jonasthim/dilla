# dilla v0.1.0-web3.9.2

Released 2026-10-21.

A client-only patch for [issue #37](https://github.com/jonasthim/dilla/issues/37), "There is no sound when watching another person's stream", follow-up. The notice that a share has no sound told everyone the same thing, and on Linux and in Firefox or Safari the advice could not work. This release names what each browser can do, and lets a share without sound take its sound from an audio input.

## What's new

- **The no-sound notice gives advice for your browser.** The person sharing sees one of three notices:
  - in Firefox (and browsers built on it) and Safari: this browser can't share sound; Chrome or Edge can share a browser tab with its sound;
  - in Chrome or Edge on Linux: only a browser tab can carry sound, so share a tab and keep "Also share tab audio" ticked;
  - in Chrome or Edge on Windows, ChromeOS or macOS: share a browser tab, or tick "Also share system audio" when you pick a screen.
- **A "sound from" picker for a share without sound.** When a share has no sound of its own, a **sound from** list appears under the call controls: none, then every audio input the browser lists. Pick one and it is published as the stream's sound, end-to-end encrypted like the rest of the call. Everyone watching gets it through the same per-person volume and mute. Choosing none, or stopping the share, removes it. A tab's or a screen's sound from the browser always wins, and then the list is not shown.
- **The call's own microphone is never offered** in the list, so a share cannot send your mic back to the call.
- **An echo warning for monitor devices.** Picking a "Monitor of …" device (everything your computer plays, including this call) shows a warning that others will hear themselves. Picking it is still allowed.
- **Notice button.** When the list has at least one source, the notice adds "You can also pick a sound source for the stream." and a **pick a sound source** button that opens the list.
- **A PipeWire recipe in the voice guide** for sending one app's sound as an input: a null sink, a loopback so you still hear it, and a remapped input to pick. See [voice](../../user/voice.md#share-sound-from-firefox-or-linux).

## Fixed

- **The no-sound notice no longer suggests a Windows-only option everywhere.** Until now it said "on Windows tick 'Also share system audio'" on every platform, which did nothing on Linux, Firefox and Safari. Each browser now gets the advice above.

## Operator notes

- **Client-only.** Nothing to configure and no server change. The new browser client comes inside the `dillad` binary, so it is still a `dillad` upgrade: `install.sh --upgrade --version v0.1.0-web3.9.2`. Open tabs pick up the new build and reload.
- **Check for live calls before you upgrade.** Restarting `dillad` restarts the media server (SFU), which disconnects every live call. Run `dillad media --rooms --config=/etc/dilla/dilla.toml` first and upgrade when it reports `no live rooms`. Since web-3.9, an idle desktop parked in the AFK channel counts as a live call, so an empty-looking server can still be listed there.
- Shared sound from the picker is end-to-end encrypted like voice, the same as tab or system sound.
- **Rollback to web3.9.1** is safe. The picker is client-only, and a web3.9.1 tab shows the older notice and has no picker.

## Known limits

- A translated "Monitor of …" label gets no echo warning.
- The Firefox picker is not covered by an automated test. Firefox's fake test devices list only the call's own microphone, so the picker has nothing to show there. It is checked by hand.
- Chromium on Linux hides monitor devices from the list. Use the remap-source recipe in the voice guide there instead of picking a monitor.
- The web3.9 and web3.9.1 known limits still hold.
