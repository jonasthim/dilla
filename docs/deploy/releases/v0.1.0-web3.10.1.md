# dilla v0.1.0-web3.10.1

Released 2026-10-21.

A client-only patch for the call dock's numbers, from Jonas's report on the deployed web3.10: alone in a call, muted and deafened, the dock read `0 ms · ↑1 ↓— kb/s`. Nothing about messages, keys or calls changes on the wire.

## What's fixed

- **The down rate is 0 when nothing is received, not a dash.** With nobody sending you anything, LiveKit has no receiving connection at all, and the dock took that for a failed reading. Now a missing receiving connection reads ↓0. A dash is shown only for a reading that failed, after the last value is kept for one tick.
- **Single-connection calls count their incoming media.** When the call runs on one peer connection, incoming media is reported with the outgoing media. The dock now counts incoming media from every connection that has it, once per stream.
- **A ping under 1 ms reads "<1 ms".** A round trip that rounds to 0 ms (a connection on the same network) used to read "0 ms", which looked like a missing reading.

## Operator notes

- **Client-only.** Nothing to configure and no server change. The new browser client comes inside the `dillad` binary, so it is still a `dillad` upgrade: `install.sh --upgrade --version v0.1.0-web3.10.1`. Open tabs pick up the new build and reload.
- **Check for live calls before you upgrade.** Restarting `dillad` restarts the media server (SFU), which disconnects every live call. Run `dillad media --rooms --config=/etc/dilla/dilla.toml` immediately before the restart, and upgrade only when it reports `no live rooms`. The answer goes stale, so a check made ten minutes earlier proves nothing. Running the check and the installer in one command keeps the gap small.
- **Check the journal grep against a known call window first.** To confirm that nothing is attached, look for API journal entries for posts to `calls/{id}/stats` (every attached device posts one every 10 s, so none in the last 2 minutes means nothing is attached). Before you trust an empty result, run the same grep over a window in which you know a call was live and check that it finds the posts. A pattern that matches nothing proves nothing. An idle desktop parked in the AFK channel counts as a live call.
- The dock's ping and rates are read in the browser from its own connection and are not sent anywhere.
- **Rollback to web3.10** is safe. A web3.10 tab shows the old dash.

## Known limits

- The dock's "↓0" also shows while others are in the call but all muted or silent: it counts bytes received, and silence sends almost none.
- The web3.10 known limits still hold.
