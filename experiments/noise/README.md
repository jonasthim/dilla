# Private microphone enhancement

DeepFilterNet3 is integrated into the application's shared microphone processor, encrypted calls and local microphone test. **It is not qualified and no Krisp parity is claimed.** The ordinary build retains the existing Lightweight default. Explicit evaluation and opt-in beta builds enable Automatic → DeepFilterNet3 → Lightweight → browser fallback.

## Run the feature

1. Install the repository dependencies and build its existing core WASM as documented by the project.
2. Run `npm run noise:prepare`. This explicitly downloads pinned source/build dependencies and builds the model WASM locally. It requires git, tar, Rust with wasm32-unknown-unknown, wasm-pack and Python 3. Review `asset-lock.json` changes. Cached clean upstream checkouts can be supplied using `NOISE_DEEPFILTER_SOURCE` and `NOISE_HUSH_SOURCE`.
3. Run `npm run noise:build`, or `DILLA_NOISE_MODE=evaluation npm run dev -w @dilla/web` with the usual local server. Select **Automatic** in Voice settings. The microphone test and calls show **DeepFilterNet3** and an evaluation notice when initialization succeeds.
4. `npm run build -w @dilla/web` without that environment setting produces the ordinary build. It contains no DeepFilter model, WASM, worker or glue. Hush and GTCRN are always comparison-only dependencies.

The build-time plugin verifies the local asset hashes and emits content-hashed same-origin files, with license notices. Runtime verifies hashes before inference. There are no CDN downloads, license calls, uploads, telemetry, SharedArrayBuffer requirements or new isolation headers. The server's static-file MIME table gains `.bin` support; APIs, encryption and screen-share processing are unchanged. The exact weights license review remains open; do not distribute the evaluation build as a qualified release.

Automatic only migrates legacy On preferences when the build is qualified. Explicit Off and Lightweight choices persist. Off disables application/browser suppression where supported and preserves echo cancellation. Browser constraints are verified from actual settings; browsers that fix suppression at capture time require capture restart. All failures and effective fallback modes are visible.

## Opt-in beta

Run `npm run noise:build:beta` (equivalent to `DILLA_NOISE_MODE=beta npm run build -w @dilla/web`). Beta builds use the exact pinned runtime artifacts in `third_party/noise/`; they do not need the comparison harness's asset acquisition. For local development use `DILLA_NOISE_MODE=beta npm run dev -w @dilla/web` after extracting RNNoise with its media preparation script. The output is the normal application in `packages/web/dist`, with its model assets served from the same origin. This command builds locally. The release workflow selects beta only for explicit `vX.Y.Z-noise-beta.N` tags; ordinary tags keep the ordinary profile.

In **Settings → Voice → noise suppression**, users see **Automatic (beta)**, **Lightweight**, and **Off**. The explanation is visible before opting in. New users and legacy On preferences stay on Lightweight; explicit Off and Lightweight are preserved. Users who previously selected Automatic keep that explicit choice. Enhanced assets are fetched only when Automatic starts a call or microphone test. Active enhancement shows a beta status, and failures still show the effective fallback and its reason. Choose Lightweight to leave the beta, including during a call. The microphone test remains limited to ten seconds in memory and unavailable during calls.

The owner accepted offering a beta with possible glitches, extra delay and fallback, and subsequently explicitly requested its release after the model-license uncertainty was disclosed. That decision does not convert failed qualification into a pass or assert new upstream licensing evidence. The measured latency target, endurance failures, missing listening comparison and incomplete device coverage remain in [findings](results/FINDINGS.md). Linux WebKit produced no output; physical Safari/iOS and Android remain untested. See the [beta release notes](../../docs/deploy/releases/v0.1.0-noise-beta.1.md).

To remove beta availability from a deployment, rebuild without `DILLA_NOISE_MODE` and replace its web distribution. Existing Automatic preferences then use the ordinary Lightweight/browser fallback. No database migration or protocol change is involved. For a user's immediate rollback, select Lightweight. [Local beta readiness](results/beta-readiness.json) records the earlier beta UI build separately from historical performance measurements; release packaging retains the same pinned model/WASM and gets a new implementation identity.

The beta smoke tests run against the built application from `e2e`: `DILLA_NOISE_MODE=beta npx playwright test --config playwright.voice.config.ts noise-beta.spec.ts enhanced-fallback.spec.ts microphone-test.spec.ts --project=chromium-voice`. They check opt-in, lazy assets, preview, encrypted delivery, leaving the beta and startup fallback. They do not replace the strict latency/endurance tests below.

Inference runs in a Worker, connected directly to a lightweight AudioWorklet by MessageChannel. Where an actual audio-track probe succeeds, direct capture transfers its readable stream to the inference Worker and avoids the extra Web Audio input buffer: six transferable buffers, at most 20 ms capture blocks, and three completed output frames plus two render quanta provide scheduling headroom. Other browsers retain the four-buffer AudioWorklet input path. Both paths keep fixed playout timelines and discard late samples rather than accumulating delay after a stall. The output context uses the audio-device clock; a timer-driven silent sink can accumulate clock lag. Inference is primed with synthetic audio before live capture, then its histories are cleared. PCM framing, inference and buffer recycling run in the Worker/Worklet; browser stream-transfer scheduling can still be affected by host load. Worker cancellation is acknowledged before shutdown; each privacy epoch owns a fresh track clone, with bounded cleanup if the Worker hangs. Privacy epochs reject stale output; capture discontinuities reset model and detector history. Reset clears recurrent state, FFT overlap and feature history without recompiling the model. PTT and mute close capture and output independently of the engine. RNNoise detects raw speech separately; enhanced audio is never fed through RNNoise. DeepFilter's existing 30 ms signal delay provides a 20 ms VAD onset allowance; the Lightweight path uses an explicit 20 ms onset buffer. Three consecutive unhealthy intervals or sustained inference overload cause a one-way downgrade. Neither engine automatically oscillates back to DeepFilterNet.

## Reproduce the evaluation

`npm run noise:test` checks corpus/reference validation, blind randomization, release gating, delay correlation, actual WASM reset and comparison output. The reset/inference tests require prepared local assets. The repository media suite covers buffers, mute/PTT, lifecycle and processor selection.

`node experiments/noise/browser-run.mjs chromium deepfilter` runs the same processor against a synthetic source, without opening a microphone. `firefox` and `webkit` are also supported; Playwright WebKit on Linux is not physical Safari qualification. On Linux the runner discovers an existing per-user PulseAudio/PipeWire socket if the environment omitted `PULSE_SERVER`; it does not start or configure host services.

`node experiments/noise/browser-run.mjs chromium deepfilter /absolute/speech.wav vad` uses a file-backed fake microphone for up to ten seconds, with browser suppression disabled. The runner records actual AEC/AGC/NS settings, raw-to-processed waveform correlation, buffer/inference metrics, browser/hardware versions, model and input hashes, silence while muted and third-party requests. Repeat with `rnnoise` and `current` (browser suppression plus RNNoise). Capture output taps include browser MediaStream buffering; reported delay is not replaced with the paper's algorithmic latency. Silence or weak correlation produces an unmeasured result, not a pass.

`node experiments/noise/latency-run.mjs` runs a calibrated direct-track latency regression in seven fresh Chromium instances: a known 40 ms delay check, then six enhanced runs alternating idle and main-thread load. It observes raw and outgoing tracks directly, without adding a monitoring AudioContext or subtracting a bypass estimate. Three correlated speech windows include delivery-clock alignment; the report uses the worst window, not a claim about every sample's maximum delay. Prepare the FLEURS corpus first, or supply a consented WAV as the first argument and a report path as the second. Run performance checks without concurrent builds/tests. Set `DILLA_NOISE_TRANSPORT=worklet` on either latency runner to compare the alternate AudioWorklet input path; the override belongs only to the test harness.

From `e2e`, `DILLA_NOISE_MODE=evaluation npx playwright test --config playwright.voice.config.ts enhanced-latency.spec.ts --project=chromium-voice --repeat-each=3` repeats that measurement inside actual encrypted calls. `DILLA_NOISE_RUN_PREFIX=/absolute/report-prefix` preserves each repeat separately. These regression checks require <=80 ms complete added delay, <0.1% underruns, no drops or fallback, and p99 inference <8 ms. Their zero-drop assertion is deliberately stricter than the planned duration-based underrun threshold; report both verdicts when they differ. These synthetic Linux checks do not qualify physical devices or listening quality.

`DILLA_NOISE_MODE=evaluation DILLA_NOISE_SECONDS=1800 npx playwright test --config playwright.voice.config.ts enhanced-latency.spec.ts --project=chromium-voice`, from `e2e`, measures the start and end of a 30-minute speech call between two encrypted peers, with 6 ms of main-thread work per 16 ms on the sender. It checks continuous processor health and fresh authenticated remote audio after the load phase. PCM is retained only for the first and last eight-second measurement windows, then discarded. Use the host's audio backend. Results are stored in `results/chromium-call-latency-30min.json`; a short run does not satisfy the duration gate. `enhanced-noise.spec.ts` separately exercises actual preview and encrypted-call PTT release/hold. These tests are skipped in ordinary builds. Existing voice tests cover screen-share audio, devices, reconnects and call cleanup.

## Speech corpus and comparisons

`python experiments/noise/fleurs-corpus.py` prepares 30 English and 30 Swedish speech clips from Google's CC-BY-4.0 FLEURS dataset. It needs Python requests, pyarrow, numpy and ffmpeg. Downloads are verified against pinned parquet hashes. Source IDs, attribution, transforms, transcripts and WAV hashes are recorded in `results/fleurs-corpus.json`; audio stays in ignored `output/fleurs/`. These 16 kHz sources are resampled to 48 kHz. Synthetic keyboard/fan noise and FLEURS speech mixtures are explicitly labeled. This starter corpus does **not** complete natural-noise/full-band/onset qualification; dogs and matched Krisp references are missing.

`node experiments/noise/compare.mjs experiments/noise/output/fleurs/corpus.json experiments/noise/output/fleurs-comparison` processes identical inputs through RNNoise, DeepFilterNet3, GTCRN and native Hush. The checked-in `results/offline-fleurs.json` records 240 real inference outputs, hashes and timings. These timings exclude capture, VAD and browser scheduling. Hush's native performance does not predict browser performance.

For release qualification provide at least 60 distinct licensed/consented 48 kHz mono PCM16/float32 WAVs covering English, Swedish, clean, quiet, onset, keyboard, fan, dog, TV and overlapping speech. Record equally loud competing speakers separately. Example manifest entry:

```json
{"clips":[{"id":"sv-onset-01","file":"sv-onset-01.wav","sha256":"64 lowercase hex digits","language":"sv","categories":["quiet","onset","keyboard"],"consent":"Consent record or license reference","reference":{"file":"sv-onset-01-krisp.wav","sha256":"64 lowercase hex digits","inputSha256":"same input hash","version":"exact Krisp/host version","captureSettings":{"sampleRate":48000,"channels":1,"echoCancellation":true,"autoGainControl":true,"noiseSuppression":false},"lawfulUse":"Reference acquisition permission"}}]}
```

Acquire Krisp outputs lawfully from identical inputs and matched capture settings. Establish alignment and annotate onset transcripts; do not substitute online demos. `node experiments/noise/listen.mjs output-directory/report.json blind-directory 42` makes a local blind listening page. Keep its key away from listeners, use distinct seeds for at least five listeners, and score naturalness, noise reduction, overall quality and missing words. Nothing is uploaded. Combine exported ratings and per-listener keys as `{"listeners":{"alice":{"seed":42,"key":[...]},"bob":{"seed":43,"key":[...]}}}`.

## Qualification gate

`node experiments/noise/qualify.mjs corpus.json runtime.json ratings.json blind-key.json evidence.json output-index.json experiments/noise/results/release-qualification.json` checks all evidence. Every category's paired mean must be at least -0.25 relative to Krisp; extra missing words fail. Uncertainty is reported across listener means. Missing evidence is a failed gate.

Runtime records must cover desktop Chrome, Firefox, Safari, Android Chrome and iOS Safari, each with a loaded call of at least 1800 seconds, complete measured added delay <=80 ms (target <=60), underruns <0.1%, and p99 inference <80% of the frame budget. Required fields: `platform`, `durationSeconds`, `loadedCall`, `addedDelayMs`, `underruns`, `buffers`, `p99ProcessingMs`, `frameMs`.

The mandatory evidence manifest has `schema:1`, `candidate:"deepfilter"`, `assetLockSha256`, `implementationSha256`, SHA-256 fields for `corpus`, `runtime`, `ratings`, `blindKey`, `outputIndex`, and `clips:[{id,inputSha256,outputs:{deepfilter,krisp}}]`. Runtime rows and the output index must name the same engine/model/implementation. Blind keys include verified input/output hashes. All input JSON files must live within the repository so release builds can re-read and recompute qualification. Missing or mismatched provenance fails; current identity is never assigned to old measurements. `noise-build.json` records the measured application's build identity.

A separate `results/release-review.json` must identify reviewer/date, matching `assetLockSha256` and `implementationSha256`, exact model license evidence (`modelLicense: {cleared, spdx, source}`), and checks for `matchedCapture`, `onsetWords`, `lifecycle`, `encryption`, `screenShare`, `sameOriginAssets`, `physicalBrowserMatrix`. Its `evidence` array names repository-relative files and SHA-256 hashes. Then `DILLA_NOISE_MODE=qualified npm run build -w @dilla/web` verifies both qualification and the hashed review evidence before enabling the enhanced default. The beta profile neither satisfies this gate nor enables default migration. Changing model assets requires new matching evidence.

See [findings](results/FINDINGS.md), [qualification status](results/qualification.json) and [exact artifact license audit](licenses/README.md). Five listeners, lawful Krisp references and physical devices cannot be substituted with synthetic or automated scores.

For an isolated Linux WebKit dependency setup, `NOISE_WEBKIT_EXECUTABLE` can name a local wrapper around the installed Playwright MiniBrowser. This is a test-runner override only; it is recorded as Linux WebKit, regardless of the Safari-shaped user agent. It is not a physical Safari pass.
